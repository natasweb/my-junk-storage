このガイドでは、カスタムエージェントの作成および使用時に発生する一般的な問題の診断と解決方法について説明します。

## 設定エラー

### 無効なJSON構文

**問題**：JSONの解析エラーにより、カスタムエージェントの読み込みに失敗します。

**症状：**

- 「無効なJSON」または「構文エラー」と表示されるエラーメッセージ
- `/agent list` にカスタムエージェントが表示されない
- デフォルトのエージェント動作に切り替わる

**解決策：**

- JSONバリデータやリンターを使用してJSONを検証する
- よくあるJSONエラーを確認してください：
  - 配列要素間やオブジェクトのプロパティ間のコンマが欠落している
  - 最後の要素の後に余分なコンマがある
  - 括弧や中括弧の不一致
  - 文字列値内のエスケープされていない引用符
- `/agent schema` を使用して構成構造を検証する

### スキーマ検証エラー

**問題**: カスタムエージェントの設定が、期待されるスキーマと一致していません。

**症状：**

- 未知の設定フィールドに関する警告
- 設定と一致しないカスタムエージェントの動作
- 必須フィールドの欠落エラー

**解決策：**

- `/agent schema` を使用して、設定をスキーマと照合してください
- フィールド名にタイプミスがないか確認してください（例：`allowedTools` 対 `allowedTool`）
- データ型がスキーマの要件と一致しているか確認してください（配列と文字列、ブール値と文字列など）

## エージェントの読み込みに関する問題

### エージェントが見つからない

**問題**：カスタムエージェントがリストに表示されない、または使用できない。

**症状：**

- `/agent list` カスタムエージェントが表示されない
- 警告なしにデフォルトのエージェントに切り替わる

**解決策：**

- カスタムエージェントファイルが正しい場所に配置されていることを確認してください：
  - グローバル：`~/.kiro/agents/[name].json`
  - ワークスペース：`.kiro/agents/[name].json`
- ファイルのアクセス権限を確認し、ファイルが読み取り可能であることを確認してください
- ファイル名が、使用しようとしているカスタムエージェント名と一致していることを確認してください
- ファイルの拡張子が「`.json`」であることを確認してください

### 読み込まれているエージェントのバージョンが間違っている

**問題**：想定とは異なるバージョンのカスタムエージェントが読み込まれています。

**症状：**

- カスタムエージェントの動作が、最近行った設定変更と一致しません
- カスタムエージェントの競合に関する警告メッセージ
- ツールの利用可能状態や権限に予期しない状態が生じている

**解決策：**

- ローカルディレクトリとグローバルディレクトリ間で、カスタムエージェント名の競合がないか確認してください
- ローカルのカスタムエージェントは、グローバルなカスタムエージェントよりも優先されることに注意してください
- `/agent list` を使用して、どのバージョンが読み込まれているかを確認してください
- 必要に応じて、競合しているカスタムエージェントファイルを削除または名前を変更する

## ツールの権限に関する問題

### ツールが利用できない

**問題**: カスタムエージェントが、設定したツールにアクセスできません。

**症状：**

- 不明なツールまたは利用できないツールに関するエラーメッセージ
- `allowedTools`内のツールに対する権限をカスタムエージェントが要求している
- MCPサーバーのツールが機能しない

**解決策：**

- `tools`配列内のツール名の綴りが正しいことを確認してください
- MCPツールについては、`mcpServers`内でサーバーが適切に設定されていることを確認してください
- MCPサーバーが稼働しており、アクセス可能であることを確認してください
- MCP ツールには正しい構文を使用してください：`@server_name/tool_name`
- 組み込みツールのドキュメントを参照して、組み込みツールの名前を確認してください

### /tools コマンドが空のリストを返す

**問題**：`/tools` コマンドを実行しても、利用可能なツールが表示されないか、期待される数よりも少ないツールしか表示されません。

**症状：**

- `/tools` 空のリストが返される
- ツール一覧に期待されるツールが含まれていない
- カスタムエージェントに機能がないように見える

**一般的な原因：**

- カスタムエージェントの設定で、`tools`配列が空になっている
- `tools`配列内のツール名に誤字がある
- MCPサーバーのツール名が正しくない（サーバープレフィックスが欠落している）
- ツールの読み込みを妨げるMCPサーバーの設定上の問題

**解決策：**

- カスタムエージェントの設定に、有効なツール名を含む`tools`配列が含まれていることを確認してください
- ツール名のスペルが正しいか確認してください（大文字と小文字を区別します）
- MCPツールについては、正しいサーバープレフィックス付き形式（`@server-name/tool-name`）を使用していることを確認してください
- デフォルトのエージェントを使用してテストを行い、`/tools` 経由でツールが利用可能であることを確認してください
- 外部ツールを使用している場合は、MCP サーバーのステータスを確認してください

### 予期しない権限の要求が表示される

**問題**：事前に承認済みだと思っていたツールに対して、カスタムエージェントが権限の要求を表示する。

**症状：**

- `allowedTools` にリストされているツールに対して権限の確認プロンプトが表示される
- カスタムエージェントの設定にもかかわらず、ワークフローが中断される

**解決策：**

- ツールが「`tools`」と「`allowedTools`」の両方の配列にリストされていることを確認する
- 2つの配列間でツール名に誤字がないか確認する
- MCP ツールについては、`allowedTools` にサーバープレフィックス付きの完全な名前を使用してください
- `toolAliases` が正しく適用されていることを確認する

## エージェントの動作のデバッグ

### コンテキストまたはリソースの欠落

**問題**：カスタムエージェントが、想定されるファイルやコンテキストにアクセスできないようです。

**解決策：**

- `resources`配列内のファイルパスが正しく、ファイルが存在することを確認してください
- `resources`内のグロブパターンが、対象のファイルと一致していることを確認する
- フックコマンドが正常に実行され、出力が生成されていることを確認してください
- フックコマンドを手動でテストし、お使いの環境で正常に動作することを確認してください
- コマンドが途中で切断される場合は、フックのタイムアウト設定を確認してください

### MCP サーバーの問題

**問題**：MCP サーバーが動作していない、またはツールが利用できない。

**解決策：**

- MCPサーバーのコマンドが正しいこと、および実行ファイルがPATHに設定されていることを確認してください
- 必要な環境変数が設定されているか確認してください
- MCPサーバーを個別にテストし、正常に動作していることを確認してください
- MCP サーバーのログを確認し、エラーメッセージがないか確認する
- サーバーの起動に時間がかかる場合は、タイムアウト値を延長してください

### エージェント設定のテスト

カスタムエージェントの設定を体系的にテストするには：

1. JSONバリデータを使用してJSONの構文を検証する
2. `/agent schema` を使用して、設定をスキーマと照合する
3. `/agent list` を使用してエージェントの読み込みをテストする
4. `/agent swap [name]` を使用してカスタムエージェントに切り替える
5. 各ツールを個別にテストし、アクセスと権限を確認する
6. リソースとフックが期待通りのコンテキストを提供していることを確認する
7. 一般的なワークフローをテストし、カスタムエージェントが期待どおりに動作することを確認する
