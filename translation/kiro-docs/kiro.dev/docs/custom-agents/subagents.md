サブエージェントを使用すると、特定のタスクを、独自の隔離されたコンテキストで実行されるエージェントに委譲することができます。メインエージェントは、タスクの並列処理、専用ツール、またはコンテキストの隔離が有効な場合にサブエージェントを生成し、処理が完了したら結果を集約します。

| 機能 | IDE | CLI | Web | モバイル |
| --- | --- | --- | --- | --- |
| サブエージェントの自動起動 | ✓ | ✓ | ✓ | ✓ |
| サブエージェントの明示的な呼び出し | ✓ | ✓ | ✓ | ✓ |
| サブエージェントとしてのカスタムエージェント | ✓ | ✓ | ✓ | — |
| 並列実行 | ✓ | ✓ | ✓ | ✓ |

Web では、`.kiro/agents/` にコミットされたカスタムエージェントを、Kiro の[組み込みサブエージェント](https://kiro.dev/docs/custom-agents/subagents/#built-in-sub-agents)と同様にサブエージェントとして呼び出すことができます。モバイル版では、組み込みのサブエージェントのみが使用されます。

## サブエージェントの仕組み

1. **タスクの割り当て** - タスクを記述します（または、メインエージェントが委任によってメリットが得られるタスクを特定します）。
2. **エージェントの選択** - Kiroは、タスクと利用可能なエージェントに基づいて、適切なエージェント構成を選択します
3. **分離された実行** — サブエージェントは、独自のコンテキストウィンドウ、ツール、および権限を持って実行されます
4. **結果の返却** - 処理が完了すると、サブエージェントは結果をメインエージェントに返します

任意の[カスタムエージェント](https://kiro.dev/docs/custom-agents/)をサブエージェントとして呼び出すことができます。メインエージェントは、エージェントの`description`フィールドに基づいて自動的にエージェントを選択しますが、明示的に指定することも可能です：

```text
Use the code-reviewer agent to analyze src/auth/ for security issues
```

## サブエージェントが継承するもの

サブエージェントはワークスペース環境を共有しますが、会話コンテキストは分離された状態で実行されます：

| メインエージェントと共有されるもの | サブエージェントごとに分離 |
| --- | --- |
| [ステアリングファイル](https://kiro.dev/docs/steering/) | 会話履歴 |
| [MCPサーバー](https://kiro.dev/docs/mcp/) | コンテキストウィンドウ |
| ワークスペースファイルへのアクセス | [仕様](https://kiro.dev/docs/specs/)状態 |
| [権限](https://kiro.dev/docs/permissions/)設定 | [フックの](https://kiro.dev/docs/hooks/)トリガー |

## 組み込みサブエージェント

Kiroには、適切な場合に自動的に使用される2つの内部サブエージェントが含まれています：

- **コンテキスト収集** - プロジェクト構造を調査し、関連するファイルやコンテキストを収集します
- **汎用** - デフォルトのエージェント設定を使用して、あらゆる種類の並列タスクを処理します

これらを設定する必要はありません。メインエージェントが必要に応じてこれらを使用します。

## 並列実行

サブエージェントは並列で実行され、それぞれが独立して動作します。これは次のような場合に役立ちます：

- 複数のファイルを同時にリファクタリングする場合
- 複数のトピックを並行して調査する
- 独立した分析トラックの実行

```text
Refactor these three services to use the new auth middleware - do them in parallel
```

## タスクの依存関係

サブエージェントは、タスク同士が相互に依存する有向非循環グラフ（DAG）をサポートしています。メインエージェントは、タスクグラフ全体を事前に計画し、適切な順序で実行します。具体的には、独立したタスクを並行して実行し、依存関係があるタスクについては、依存するタスクが完了するのを待ってから開始します。

```text
  ┌─────────────┐
  │  1. Analyze  │
  │ dependencies │
  └──────┬───────┘
         │
  ┌──────▼───────┐
  │ 2. Refactor  │
  │   modules    │
  └──────┬───────┘
         │
  ┌──────▼───────┐
  │  3. Run and  │
  │  fix tests   │
  └──────────────┘
```

## レビューのループ

あるステージの出力が、さらなる作業が必要であることを示した場合、そのステージは前のステージに戻ることができます。例えば、レビュー担当者が修正のために作業を実装担当者に差し戻す場合などです。

```text
Implement the feature, then have a reviewer check it and send it back for fixes until it passes
```

エージェントは、以下の要素を用いてループするパイプラインを構築します：

- **ターゲット** - ループがトリガーされた際に再実行されるステージ
- **トリガー** — ループを起動するステージ出力のテキスト（例：`NEEDS_CHANGES`）
- **max_iterations** — 安全上限（1～10の間）

制約：

- ステージは自分自身へループバックすることはできません
- 相互ループ（A → B → A）は拒否されます
- トリガーは4文字以上でなければならない

## ツールの利用可能性

デフォルトのサブエージェントには、メインエージェントと同じ組み込みツール（`read`、`write`、`shell`、`web_search`、`web_fetch`、および設定済みのMCPツール）が備わっています。

カスタムエージェントに委任する場合、サブエージェントはそのエージェントの `tools` および `permissions` の設定を使用します。カスタムエージェントの設定にリストされていないツールは、サブエージェントでは使用できません。CLI V3 および IDE では、親セッションの権限がサブエージェントのツール呼び出しにも適用されます。 「[サブエージェントの権限」](https://kiro.dev/docs/custom-agents/subagents/#sub-agent-permissions)を参照してください。

## サブエージェントへのアクセス権の設定

CLI 2.x では、[エージェント設定](https://kiro.dev/docs/custom-agents/configuration-reference/)内の `toolsSettings.subagent` を使用して、どのエージェントを起動できるか、およびどのエージェントが承認プロンプトなしで実行されるかを制御します:

json

```json
{
  "toolsSettings": {
    "subagent": {
      "availableAgents": ["reviewer", "tester", "docs-*"],
      "trustedAgents": ["reviewer", "tester"]
    }
  }
}
```

| フィールド | 説明 |
| --- | --- |
| `availableAgents` | このエージェントが起動できるエージェントのグロブパターン。省略するとすべて許可されます。 |
| `trustedAgents` | 承認プロンプトなしで起動するエージェント。 |

CLI V3 では `toolsSettings` は無視されます。CLI V3 でエージェントが起動できるエージェントを制限するには、`subagent` の代わりに、そのエージェントの `tools` に `subagent/<name>``subagent` エントリを列挙してください`tools``invoke_sub_agent``permissions`。`@builtin` や `*`

json

```json
{
  "tools": ["read", "write", "shell", "web", "subagent/reviewer", "subagent/tester"],
  "permissions": {
    "rules": [
      { "capability": "subagent", "match": ["reviewer", "tester"], "effect": "allow" }
    ]
  }
}
```

サブエージェントが使用できるツールを制限するには、親エージェントではなく、**サブエージェント自身の設定ファイル**内で`tools`を設定してください。

## サブエージェントの権限

Kiro がサブエージェントのツール呼び出しを承認する方法は、CLI のバージョンによって異なります。

|  | CLI 2.x | CLI V3 |
| --- | --- | --- |
| 読み取られるエージェントフィールド | `allowedTools` および `toolsSettings` | `permissions``allowedTools`および`toolsSettings`は無視されます) |
| プロンプトなしでサブエージェントを起動する | `toolsSettings.subagent.trustedAgents` にエージェントを追加 | `subagent` の機能を追加`allow` ルール |
| サブエージェント独自の事前承認済みツール | 親セッションで許可されていなくても、プロンプトなしで実行する | 親セッションでも許可されている場合にのみ、プロンプトなしで実行する |

CLI V3 および IDE では、Kiro はすべてのサブエージェントのツール呼び出しについて、次の 2 つのポリシーに基づいてチェックを行います：

- 親セッションのポリシー。これには、ユーザーおよびワークスペースの`permissions.yaml`、親エージェントの`permissions`、およびセッションの早い段階で付与した承認が含まれます。
- サブエージェント自身の`permissions`。

より厳しい結果が優先されます：

- いずれかのポリシーの`deny`が呼び出しを拒否します。
- いずれかのポリシーの`ask`ルールが適用される場合、確認プロンプトが表示されます。
- 親セッションのポリシーにその呼び出しに関するルールがない場合、サブエージェント自身のルールで許可されている場合でも、Kiroは確認を求めます。

サブエージェントの `allow` ルールは、そのエージェントがトップレベルのエージェントとして実行されている場合（たとえば、`kiro-cli chat --agent <name>` を使用している場合など）にのみ有効になります。サブエージェントのルールに言及されていない呼び出しは、親セッションのポリシーに従います。`permissions` ブロックを持たないサブエージェントは、親セッションのポリシーの下で実行されます。

CLI V3 でサブエージェントのツール呼び出しをプロンプトなしで実行するには、サブエージェントの `allow` ルールを以下のいずれかに追加します：

- 親エージェントの`permissions.rules`。親エージェントには、MCPサーバーやツール自体は必要ありません。
- ユーザースコープの`~/.kiro/settings/permissions.yaml`。これらのルールはすべてのエージェントに適用されます。
- ワークスペーススコープの`permissions.yaml`。これらのルールは、そのワークスペース内のすべてのエージェントに適用されます。

たとえば、`data-analyst`という名前のサブエージェントが、`analytics`のMCPサーバーからのすべてのツールを許可する場合、親エージェントには次のようなルールが必要です：

json

```json
{
  "tools": ["read", "write", "shell", "subagent/data-analyst"],
  "permissions": {
    "rules": [
      { "capability": "subagent", "match": ["data-analyst"], "effect": "allow" },
      { "capability": "mcp", "match": ["analytics/*"], "effect": "allow" }
    ]
  }
}
```

すべてのツールを信頼するセッションでは、`--trust-all-tools`は、通常であれば確認プロンプトが表示されるはずのサブエージェントによるツール呼び出しを承認します。`deny`のルールは引き続き適用されます。

## ワークスペース固有の動作

ワークフローが無効になっている場合、サブエージェントは並行して実行され、メインエージェントはすべてが完了するまで待機してから処理を続行します。ワークフローが有効になっている場合、メインエージェントは代わりにカスタムエージェントの委任をバックグラウンドのワークフロー実行として起動するため、親の会話を引き続き行いながら、**「ワークフロー」**の下で実行状況を監視することができます。委任された各エージェントには、独自のコンテキストウィンドウがあります。

サブエージェントを活用して複数のタスクを同時に実行することで、開発を効率化できます。例えば、複数のチケットを並行して取得・分析するなどです。

## ベストプラクティス

1. **複雑なタスクに活用する** — 隔離や並列処理の恩恵を受ける多段階の操作において最も有用です
2. **明確な指示を与える** — 具体的なタスクの説明により、適切なエージェントの選択と良好な結果が得られます
3. **進捗を監視する** — CLI では、Ctrl+G を使用して長時間実行中のサブエージェントの状態を確認します
4. **アクセスの設定** — オーケストレーター・エージェントが生成できるエージェントを制限し、プロンプトなしで起動するエージェントを決定します。「[サブエージェントへのアクセスの設定」を](https://kiro.dev/docs/custom-agents/subagents/#configuring-sub-agent-access)参照してください。

## トラブルシューティング

| 問題 | 解決策 |
| --- | --- |
| サブエージェントが起動しない | タスクの説明が明確で、実行可能なものであることを確認してください |
| エージェントが不明 | `kiro-cli agent list` を使用してエージェント名を確認してください。未知のエージェントを指定したリクエストは、デフォルトのエージェントにフォールバックすることなく失敗します |
| ツールへのアクセス権限がない | エージェント設定の`tools`フィールドを確認してください |
| 承認プロンプトによるブロック | CLI 2.x では、`trustedAgents` にエージェントを追加して起動プロンプトをスキップし、そのエージェント自身の `allowedTools` でツールを事前承認してください。CLI V3 では、`subagent` の許可ルールを追加して起動プロンプトをスキップし、サブエージェントの `allow` ルールを親セッションのポリシーに追加してください。[「サブエージェントの権限」](https://kiro.dev/docs/custom-agents/subagents/#sub-agent-permissions)を参照してください |
| メインエージェントがサブエージェントを起動できない | オーケストレーターエージェントの`tools`配列に`subagent`を追加してください |
| 結果が不完全 | より具体的な手順を記載するか、タスクをさらに細分化してください |
