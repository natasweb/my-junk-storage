MCP サーバーは、ツール、プロンプト、およびリソーステンプレートを Kiro に公開できます。このページでは、すべてのインターフェースにおいて、これらの各機能と連携する方法について説明します。

## MCP ツールとの連携

[MCP サーバー](https://kiro.dev/docs/mcp/configuration/)の設定が完了すると、以下のいくつかの方法でそのツールを操作できます。

### 直接質問する

MCP ツールを使用する最も簡単な方法は、サーバーのドメインに関連する質問をすることです：

```
Tell me about Amazon Bedrock
```

```
How do I configure S3 bucket policies?
```

Kiroは、質問内容に基づいて適切なMCPツールを自動的に選択します。

### 特定のツールの指定

実行したい内容を記述することで、特定のMCPツールを指定してリクエストできます：

```
Search AWS documentation for information about ECS task definitions
```

```
Get recommendations for AWS CloudFormation best practices
```

### 明示的なコンテキスト（IDE）

IDE では、ツールピッカーに明示的なコンテキストを指定できます:

```
#[aws-docs] search_documentation Tell me about AWS Lambda
```

この形式では、サーバー（`aws-docs`）とツール（`search_documentation`）の両方が指定されます。

## MCPツールの管理

### MCPツールパネル

Kiroパネルには「MCPサーバー」タブがあり、以下を提供します：

- 設定済みのすべてのMCPサーバーの一覧
- 接続ステータスインジケーター
- 個々のツールの管理
- サーバーツールへのクイックアクセス

MCP パネルにアクセスするには：

1. アクティビティバーのKiroアイコンを選択します
2. 「MCPサーバー」タブに移動します
3. 接続済みのすべてのサーバーと、それらで利用可能なツールを表示します

### 個々のツールの管理

各 MCP サーバーは複数のツールを公開できます。サーバー全体に影響を与えることなく、特定のツールを有効または無効にできます:

**Kiroパネルから：**

1. Kiroパネルを開き、「MCPサーバー」に移動します
2. サーバーを展開して、利用可能なツールを表示します
3. ツールをクリックしてオプションを表示します：
   - **有効化** - 無効になっているツールを有効にします
   - **無効化** - サーバーから削除することなく、ツールを一時的に無効化します
4. 無効化されたツールには「無効」というラベルが表示され、Kiroでは利用できなくなります

**JSON設定経由：**

MCP設定内の`disabledTools`配列を使用して、特定のツールを恒久的に無効化します：

json

```json
{
  "mcpServers": {
    "github": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN", "ghcr.io/github/github-mcp-server"],
      "disabledTools": ["delete_repository", "force_push", "merge_pull_request"]
    }
  }
}
```

以下の場合に役立ちます:

- **危険な操作**（削除や強制プッシュなど）を**ブロックする**
- 使用しないツールを非表示にして、**ツールの乱立を解消する**
- Kiroが考慮するツールを制限することで**パフォーマンスを向上させる**
- ワークスペースの設定を共有する際の**チームポリシーの徹底**

### サーバーレベルの操作

MCP パネルでサーバーを右クリックすると、追加のオプションが表示されます：

- **再接続** - サーバーへの接続を再起動します
- **無効化** - サーバー全体を一時的に無効化します
- **すべてのツールを無効化** - このサーバー上のすべてのツールを一括で無効化します
- **すべてのツールを有効にする** - 以前無効にしていたすべてのツールを再度有効にします
- **MCPログの表示** - トラブルシューティング用の詳細ログを表示します

## ツールの承認プロセス

KiroがMCPツールを使用しようとする際、まずあなたの承認を求めます：

1. ツールの説明と目的が記載されたプロンプトが表示されます
2. ツールの詳細とパラメータを確認してください
3. 「承認」をクリックしてツールの実行を許可するか、「拒否」をクリックして実行を阻止してください

### 信頼できるツールの自動承認

信頼できるツールについて承認プロンプトが繰り返し表示されるのを防ぐには、MCP設定の`autoApprove`配列にツール名を追加してください：

json

```json
{
  "mcpServers": {
    "aws-docs": {
      "autoApprove": [
        "mcp_aws_docs_search_documentation",
        "mcp_aws_docs_read_documentation"
      ]
    }
  }
}
```

## MCPプロンプト

MCPサーバーは、一般的なタスク向けの事前定義された指示を提供する、再利用可能な[プロンプトテンプレートを](https://modelcontextprotocol.io/specification/2025-06-18/server/prompts)公開できます。プロンプトとは、サーバーによって定義された構造化されたメッセージテンプレートであり、カスタマイズのために入力できるオプションの引数セットを備えています。プロンプトは、チャット内の`#`メンションリストに、他のコンテキストプロバイダーと並んで表示されます。

### プロンプトへのアクセス

1. チャットの入力欄に「`#`」と入力して、コンテキストプロバイダーメニューを開きます
2. 接続済みのサーバーからのMCPプロンプトは、MCPアイコン付きでリストに表示されます
3. プロンプトを選択すると、メッセージに挿入されます

プロンプトに引数がない場合、解決されたコンテンツはチャットのコンテキストに直接挿入されます。

### 引数付きプロンプト

一部のプロンプトは、その動作をカスタマイズするための引数を受け付けます。入力が必要なプロンプトを選択すると、インラインフォームが表示され、そこにパラメータを入力してから、プロンプトがメッセージに追加されます。

たとえば、あるサーバーが、必須引数「`code`」とオプション引数「`language`」を持つ「`code_review`」というプロンプトを公開している場合などです。フォームへの入力が完了すると、サーバーがプロンプトを解決し、その結果として生成されたコンテンツがチャットのコンテキストに挿入されます。

プロンプトは常にユーザーによって開始されます。Kiroは、ユーザーが選択しない限り、サーバーにプロンプトを送信することはありません。利用可能なプロンプトのリストは、サーバーがプロンプトを追加または削除すると自動的に更新されます。

プロトコルの詳細については、[MCPプロンプト仕様](https://modelcontextprotocol.io/specification/2025-06-18/server/prompts)を参照してください。

## MCPリソーステンプレート

MCPサーバーは、特定の内容に解決されるパラメータ化されたURIテンプレートであるリソーステンプレートを公開することもできます。プロンプトと同様に、リソーステンプレートはチャット内の`#`メンションリストに表示されます。

### リソーステンプレートの利用方法

1. チャットの入力欄に「`#`」と入力して、コンテキストプロバイダーメニューを開きます
2. 接続済みのサーバーのリソーステンプレートは、MCPアイコン付きでリストに表示されます
3. テンプレートを選択すると、その引数形式が表示されます

### テンプレートのパラメータの入力

リソーステンプレートを選択すると、テンプレートのパラメータを入力するためのインラインフォームが表示されます。フォームを送信すると、Kiro が URI を解決し、その結果として得られたリソースコンテンツを会話のコンテキストとして組み込みます。

たとえば、ドキュメントサーバーが `docs://{topic}/{version}` のようなテンプレートを公開している場合があります。トピックとバージョンのフィールドに入力すると、解決されたドキュメントコンテンツが Kiro で利用可能になります。

## MCPによる情報引き出し

ツールの実行中、MCPサーバーはタスクを完了するためにユーザーからの追加情報を必要とする場合があります。これを「[情報収集」](https://modelcontextprotocol.io/specification/2025-06-18/client/elicitation)と呼びます。サーバーは処理を失敗させたり推測したりするのではなく、一時停止してユーザーに直接尋ねます。

### フォームベースの情報収集

ツールがさらなる入力を必要とする場合、必要な内容を説明するメッセージを添えて情報収集リクエストを送信します。Kiroは、要求されたデータのタイプに基づいたフィールドを持つインラインフォームを、実行タイムライン上に表示します：

| フィールドタイプ | 表示形式 |
| --- | --- |
| テキスト | テキスト入力（メールアドレスや日付などのフォーマットヒントを含む場合あり） |
| 数値 | 数値入力 |
| はい／いいえ | チェックボックス |
| 選択肢 | ドロップダウン選択 |

必須項目にはマークが付いており、サーバーから提供された場合はデフォルト値が事前に入力されています。

フォームを確認した後、回答を送信するか、リクエストを拒否するか、または破棄することができます。拒否または破棄した場合、サーバーが今後の処理を決定します。代替案を提示する場合もあれば、そのステップを完全にスキップする場合もあります。

スキーマの詳細については、[MCP 情報収集仕様](https://modelcontextprotocol.io/specification/2025-06-18/client/elicitation)を参照してください。

### URL ベースのエリシテーション

一部のサーバーでは、OAuth認証フローを完了するなど、外部URLへのアクセスを要求する場合があります。この場合、Kiroは実行タイムライン上に**「開く」**ボタン付きのURLを表示します。外部での操作が完了すると、ツールは実行を続行します。

### セキュリティ上の考慮事項

Kiroは、どのサーバーが情報を要求しているか、またどのようなデータが必要かを常に表示します。ユーザーは、いつでも任意の要求を拒否することができます。サーバーは、要求を通じてパスワードなどの機密情報を要求してはなりません。そのような要求が表示された場合は、そのサーバーを信頼できるかどうかを検討してください。

## トラブルシューティングツールの使用方法

MCP ツールの使用中に問題が発生した場合：

### ツールが応答しない

1. Kiroパネル（IDE）でMCPサーバーのステータスを確認するか、`/mcp`（CLI）を使用してください
2. MCPのログを確認し、エラーメッセージがないか確認してください
3. サーバーへの再接続を試みてください

### 結果が正しくない場合

1. リクエストをより具体的に書き直してみてください
2. タスクに適したツールを使用しているか確認してください
3. MCP サーバーに必要な権限が設定されているか確認してください

### ツールが利用できません

1. MCPサーバーが正しく設定されていることを確認してください
2. サーバーが稼働しており、接続されていることを確認してください
3. ツールを使用するために必要な権限があることを確認してください
