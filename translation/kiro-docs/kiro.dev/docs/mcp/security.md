このガイドでは、Kiro での Model Context Protocol (MCP) サーバーの設定および使用に関するセキュリティのベストプラクティスを概説し、機密情報の保護とシステムのセキュリティ維持を支援します。

## MCPのセキュリティについて

MCPサーバーは、外部サービスやAPIに接続することでKiroの機能を拡張します。MCPサーバーはサードパーティ製のコードであるため、以下のセキュリティ上の考慮事項が生じます：

- **機密情報へのアクセス**：MCPサーバーでは、APIキーやトークンが必要になる場合があります
- **外部コードの実行**：MCPサーバーはKiroのサンドボックス外でコードを実行します
- **データ転送**：Kiroと外部サービス間で情報がやり取りされます
- **ソースの検証**：使用前にソースコードを確認し、サーバーが信頼できるソースから提供されていることを検証する
- **分離**：可能な場合はサーバーを隔離された環境で実行し、付与される権限を制限してください

## セキュリティの原則

MCPのセキュリティモデルは、以下の原則に基づいて設計されています：

1. **明示的な許可**：ツールは実行前にユーザーからの明示的な許可を必要とする
2. **ローカル実行**：MCP サーバーはユーザーのマシン上でローカルに実行されます
3. **分離**：各MCPサーバーは個別のプロセスとして実行されます
4. **透明性**：利用可能なツールとその機能を確認できます

## 安全な設定

### API キーとトークンの保護

1. 機密性の高いトークンを含む**設定ファイルは、**バージョン管理システムに**コミットしない**
2. MCP サーバーが機能するために必要な**最小限の権限を持つトークンを作成してください**（たとえば、GitHub では従来のトークンの代わりに、きめ細かな個人用アクセストークンを使用してください）
3. **アクセス範囲を、**必要なリポジトリまたはリソースのみに**制限する**
4. 設定で使用される**APIキーとトークンを定期的に更新してください**
5. 可能であれば、値をハードコーディングする代わりに**環境変数を使用してください**

### 環境変数の使用

設定にトークンをハードコーディングする代わりに：

json

```json
{
  "mcpServers": {
    "github": {
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

シェルで環境変数を設定します:

bash

```bash
export GITHUB_TOKEN=your-token-value
```

### 承認済み環境変数 (IDE)

セキュリティ上の理由から、Kiro IDE は明示的に承認された環境変数のみを展開します。MCP 設定ファイル内で検出された変数のうち、承認リストに含まれるもののみが展開されます。

承認されていない環境変数を含む MCP サーバー設定を追加または変更すると、Kiro は承認が必要な変数を一覧表示したセキュリティ警告のポップアップを表示します。ポップアップから直接承認するか、設定で管理することができます。

承認済み環境変数を管理するには:

1. Kiroの設定を開く
2. 「**Mcp Approved Env Vars**」を検索
3. 展開を許可したい環境変数を追加します

これにより、MCPサーバーがシステム上の任意の環境変数にアクセスするのを防ぐことができます。

### 設定ファイルのアクセス権

MCPの設定ファイルへのアクセスを制限します：

bash

```bash
# Set restrictive permissions on user-level config
chmod 600 ~/.kiro/settings/mcp.json

# Set restrictive permissions on workspace-level config
chmod 600 .kiro/settings/mcp.json
```

## ツールの安全な使用

### ツールの承認プロセス

1. 承認前に**各ツールのリクエストを**慎重に**審査する**
2. ツールに渡される**パラメータを確認する**
3. 承認する前に、**ツールがどのような動作を行うかを理解する**
4. 現在のタスクと一致しない**不審な申請**は**すべて却下する**

### 自動承認のガイドライン

以下の条件を満たすツールのみを自動承認してください：

1. 機密性の高いシステムへの**書き込み権限を持たないもの**
2. コードが検証済みの**信頼できる提供元からのものであること**
3. ワークフローで**頻繁に使用されているもの**
4. アクセス可能な**範囲**が**限定されていること**

json

```json
{
  "mcpServers": {
    "aws-docs": {
      "autoApprove": [
        "mcp_aws_docs_search_documentation",
        "mcp_aws_docs_read_documentation"
      ]
    }
  }
}
```

## アクセス制御

- サーバーの権限設定には「最小権限の原則」を適用する
- ファイルシステムへのアクセスは必要なディレクトリのみに制限する
- 可能な限りネットワークアクセスを制限する
- `disabledTools` を使用して、危険な操作へのアクセスを制限します：

json

```json
{
  "mcpServers": {
    "github": {
      "disabledTools": ["delete_repository", "force_push"]
    }
  }
}
```

## ワークスペースの分離

プロジェクト固有のMCPサーバーには、ワークスペースレベルの設定を使用します:

```
project-a/
├── .kiro/
│   └── settings/
│       └── mcp.json  # Project A specific servers
project-b/
├── .kiro/
│   └── settings/
│       └── mcp.json  # Project B specific servers
```

これにより、以下のことが保証されます：

- MCPサーバーは、関連するプロジェクトで作業している場合のみ実行される
- トークンと設定はプロジェクト間で分離される
- セキュリティリスクは特定のワークスペース内に封じ込められる

## 認証情報の管理

- 設定ファイルにAPIキーやトークンをハードコードしてはならない
- 機密データには環境変数を使用してください
- 認証情報を定期的に更新する
- システムキーチェーンを使用して認証情報を安全に保管する

## ネットワークセキュリティ

1. リモート MCP サーバーには **HTTPS を使用してください**
2. **SSL/TLS 証明書を確認する**
3. **ファイアウォールを使用して**、MCPサーバーからの外部への接続を制限する
4. **ネットワークトラフィックを監視し、**異常なアクティビティがないか確認する
5. 広範囲なネットワークアクセスを必要とするサーバーには**注意を払う**

## 監視と監査

### MCPログの確認

1. Kiro パネルを開く
2. [出力] タブを選択する
3. ドロップダウンから「Kiro - MCP ログ」を選択します

### ツールの使用状況の監査

承認済みのツールを定期的に確認します:

1. MCPの設定を確認し、自動承認されているツールがないか確認してください
2. MCPログを確認し、ツールの使用パターンを把握する
3. サーバーのアクティビティを監視し、予期しない動作がないか確認してください
4. 頻繁に使用しなくなったツールの自動承認を解除してください

## セキュリティインシデントへの対応

MCPサーバーにセキュリティ上の問題がある疑いがある場合は：

1. 設定で直ちに**サーバーを無効化してください**
2. そのサーバーに関連付けられている**トークンやAPIキーをすべて無効化してください**
3. 接続されているサービスで**不正なアクティビティがないか確認してください**
4. **問題を**MCPサーバーの保守担当者に**報告してください**

## システムのセキュリティ

1. セキュリティパッチを適用して、**システムを最新の状態に保ってください**
2. **MCPサーバーは最小限の権限で実行する**
3. 機密性の高い MCP サーバーの実行には、**個別のユーザーアカウントを使用してください**
4. **信頼できるソースからのみMCPサーバーをインストールしてください**
5. インストール前に**ツールの説明**やドキュメント**を確認してください**
6. **セキュリティアドバイザリ**や更新**情報を**定期的に**確認してください**
