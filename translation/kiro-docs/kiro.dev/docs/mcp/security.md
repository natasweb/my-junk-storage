これらの対策を活用して、MCPサーバーへのアクセスを制限し、認証情報を保護し、実行するコードを検証してください。

## MCPのセキュリティについて

MCPサーバーは、外部サービスやAPIに接続することで、Kiroの機能を拡張します。MCPサーバーはサードパーティ製のコードであるため、以下のセキュリティ上の考慮事項が生じます：

- **機密情報へのアクセス**：MCPサーバーでは、APIキーやトークンが必要になる場合があります
- **外部コードの実行**：デフォルトでは、MCPサーバーはKiroのローカルコマンドサンドボックスの外でコードを実行します。stdioサーバーをサンドボックス内に組み込むことも可能です。「[stdioサーバーのサンドボックス化」](https://kiro.dev/docs/mcp/security/#sandboxing-stdio-servers)を参照してください
- **データ転送**：Kiroと外部サービス間で情報がやり取りされます
- **ソースの検証**：使用前にソースコードを確認し、サーバーが信頼できるソースから提供されていることを検証してください
- **分離**：可能な場合はサーバーを分離された環境で実行し、付与される権限を制限してください

## セキュリティの原則

MCPのセキュリティモデルは、以下の原則に基づいて設計されています：

1. **権限チェック**：Kiroの権限システムは、各MCPツール呼び出しを評価します。ワークスペースの信頼度および有効なルールに応じて、Kiroは呼び出しを拒否するか、承認を求めるか、または呼び出しごとの確認なしに実行します。
2. **ローカル実行**：Stdio MCP サーバーは、ユーザーのマシン上でローカルに実行されます。リモートの HTTP および SSE サーバーはプロバイダーのインフラストラクチャ上で実行され、Kiro はネットワーク経由でそれらに接続します
3. **分離**：各 Stdio MCP サーバーは、個別のローカルプロセスとして実行されます
4. **透明性**：ユーザーは、利用可能なツールとその機能を確認できます

## 安全な構成

### API キーとトークンの保護

1. 機密性の高いトークンを含む**設定ファイルは、**バージョン管理システムに**コミットしないでください**
2. MCP サーバーが機能するために必要な**最小限の権限を持つトークンを作成してください**（たとえば、GitHub では従来のトークンの代わりに、きめ細かな個人用アクセストークンを使用してください）
3. **アクセス範囲を、**必要なリポジトリまたはリソースのみに**制限する**
4. 設定で使用される**APIキーとトークンを定期的に更新してください**
5. 可能であれば、値をハードコーディングする代わりに**環境変数を使用してください**

### 環境変数の使用

設定にトークンをハードコーディングする代わりに：

json

```json
{
  "mcpServers": {
    "github": {
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

シェルで環境変数を設定します:

bash

```bash
export GITHUB_TOKEN=your-token-value
```

### 承認済み環境変数 (IDE)

セキュリティ上の理由から、Kiro IDE は明示的に承認された環境変数のみを展開します。MCP 設定ファイル内で検出された変数のうち、承認リストに含まれるもののみが展開されます。

承認されていない環境変数を含むMCPサーバー設定を追加または変更すると、Kiroは承認が必要な変数を一覧表示したセキュリティ警告のポップアップを表示します。ポップアップから直接承認するか、設定で管理することができます。

承認済み環境変数を管理するには:

1. Kiroの設定を開く
2. 「**Mcp Approved Env Vars**」を検索
3. 展開を許可したい環境変数を追加します

これにより、MCPサーバーがシステム上の任意の環境変数にアクセスするのを防ぐことができます。

### 設定ファイルのアクセス権限

MCPの設定ファイルへのアクセスを制限します:

bash

```bash
# Set restrictive permissions on user-level config
chmod 600 ~/.kiro/settings/mcp.json

# Set restrictive permissions on workspace-level config
chmod 600 .kiro/settings/mcp.json
```

## ツールの安全な使用

### ツールの承認プロセス

1. 承認前に**各ツールのリクエストを**慎重に**審査してください**
2. ツールに渡される**パラメータを確認する**
3. 承認する前に、**ツールがどのような動作を行うかを理解する**
4. 現在のタスクと一致しない**不審なリクエスト**は**すべて却下してください**

### 自動承認のガイドライン

以下の条件を満たすツールのみを自動承認してください：

1. 機密性の高いシステムへの**書き込み権限を持たないもの**
2. コードが検証済みの**信頼できるソースから提供されているもの**
3. ワークフローで**頻繁に使用されているもの**
4. アクセス可能な**範囲**が**限定されている**もの

json

```json
{
  "mcpServers": {
    "aws-docs": {
      "autoApprove": [
        "mcp_aws_docs_search_documentation",
        "mcp_aws_docs_read_documentation"
      ]
    }
  }
}
```

## アクセス制御

- サーバーの権限設定には「最小権限の原則」を適用する
- ファイルシステムへのアクセスは必要なディレクトリのみに制限する
- 可能な限りネットワークアクセスを制限する
- `disabledTools` を使用して、危険な操作へのアクセスを制限します：

json

```json
{
  "mcpServers": {
    "github": {
      "disabledTools": ["delete_repository", "force_push"]
    }
  }
}
```

### stdio サーバーのサンドボックス化

ご自身のマシン上では、ローカルコマンドサンドボックスが、エージェントのシェルコマンドに使用しているのと同じOSレベルのサンドボックス内で、stdio MCPサーバープロセスを起動できます。サンドボックスの設定で`mcpSandboxing`を`true`に設定してください。これにより、サーバーはサンドボックス化されたコマンドと同じネットワークモードおよび`sandbox_network`のホストルール下で実行されます。 リモートHTTPおよびSSEサーバーは影響を受けず、それらのネットワークアクセスはサンドボックスルールに従いません。

設定、プラットフォーム要件、およびラッピングに失敗した場合の挙動については、「[ローカルコマンドサンドボックス」](https://kiro.dev/docs/sandbox/#wrap-stdio-mcp-servers)を参照してください。

## ワークスペース固有の設定

ワークスペースレベルの設定を使用して、各プロジェクトの MCP サーバーリストを分離します:

```
project-a/
├── .kiro/
│   └── settings/
│       └── mcp.json  # Project A specific servers
project-b/
├── .kiro/
│   └── settings/
│       └── mcp.json  # Project B specific servers
```

Kiro は、プロジェクトが開かれている場合にのみ、そのプロジェクトのワークスペースサーバーを起動します。ワークスペース設定はサーバーリストを分離するものであり、サーバーへのアクセスを隔離するものではありません。[ローカルコマンドサンドボックス](https://kiro.dev/docs/mcp/security/#sandboxing-stdio-servers)やその他の OS による制限がない場合、ワークスペースサーバーは、ユーザーアカウントが利用可能なファイル、認証情報、環境変数、およびネットワークリソースに引き続きアクセスできます。

## 認証情報の管理

- 設定ファイルにAPIキーやトークンをハードコードしてはいけません
- 機密データには環境変数を使用してください
- 認証情報を定期的に更新してください
- システムキーチェーンを使用して認証情報を安全に保管してください

## ネットワークセキュリティ

1. リモート MCP サーバーには **HTTPS を使用してください**
2. **SSL/TLS 証明書を検証する**
3. **ファイアウォールを使用して**、MCP サーバーからのアウトバウンド接続を制限する
4. **ネットワークトラフィックを監視し、**異常なアクティビティがないか確認する
5. 広範囲なネットワークアクセスを必要とするサーバーには**注意を払う**

## 監視と監査

### MCPログの確認

1. Kiro パネルを開く
2. [出力] タブを選択します
3. ドロップダウンから「Kiro - MCP ログ」を選択します

### ツールの使用状況の監査

承認済みのツールを定期的に確認します：

1. MCPの設定を確認し、自動承認されているツールがないか確認してください
2. MCPログを確認し、ツールの使用パターンを把握してください
3. サーバーのアクティビティを監視し、予期しない動作がないか確認してください
4. 頻繁に使用しなくなったツールの自動承認設定を解除してください

## セキュリティインシデントへの対応

MCPサーバーにセキュリティ上の問題がある疑いがある場合は：

1. 設定で直ちに**サーバーを無効にしてください**
2. そのサーバーに関連付けられている**トークンやAPIキーをすべて無効化してください**
3. 接続されたサービスにおいて**不正なアクティビティがないか確認してください**
4. **問題を**MCPサーバーの管理者へ**報告してください**

## システムのセキュリティ

1. セキュリティパッチを適用して、**システムを最新の状態に保ってください**
2. **MCPサーバーは最小限の権限で実行する**
3. 機密性の高い MCP サーバーの実行には、**個別のユーザーアカウントを使用してください**
4. **信頼できるソースからのみMCPサーバーをインストールしてください**
5. インストール前に**ツールの説明**やドキュメント**を確認してください**
6. **セキュリティアドバイザリ**や更新**情報を**定期的に**確認してください**
