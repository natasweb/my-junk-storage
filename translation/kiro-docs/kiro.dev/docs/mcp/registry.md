IAM Identity Center を利用している Pro ティアのお客様は、MCP レジストリを通じて MCP サーバーへのアクセスを制御することができます。管理者が設定を行うと、ユーザーはレジストリで明示的に許可された MCP サーバーのみを使用できるようになります。

**レジストリなし**（デフォルト）：

- ユーザーは任意のMCPサーバーを追加できます
- エージェントファイルまたはCLI経由で設定されたサーバー
- 一元的な制御なし

**レジストリあり**（エンタープライズ）：

- 管理者が許可されるサーバーを設定します
- ユーザーはレジストリのリストから選択します
- カスタムサーバーの追加は不可 — レジストリに登録されていないサーバーは非表示になります（`mcp.json`で自身で定義したサーバーも含む）
- 一元化されたガバナンスとセキュリティ

## レジストリサーバーの追加

レジストリモードでは、利用可能なサーバーがMCPパネルに表示されます。サーバーを選択して、構成に追加してください。

## レジストリに登録されていないサーバー

レジストリが有効になっている場合、実行可能なサーバーの唯一のソースはレジストリのみとなります。`mcp.json`（グローバル `~/.kiro/settings/mcp.json` またはワークスペース `.kiro/settings/mcp.json`）で定義したサーバーは、その名前がレジストリのエントリと一致する場合にのみ実行可能です。それ以外のものはすべて非表示となり、決して起動されません。これには、レジストリが有効になる前に動作していたサーバーも含まれます。

IDE では、非表示のサーバーは個別のエントリとしてではなく、MCP パネルに「N 台のサーバーが非表示」という通知として表示されます。レジストリに登録されていないサーバーを実行するには、管理者に追加を依頼してください。

Kiro CLI V3 セッションでは、名前が一致するだけでは不十分です。 レジストリサーバーは、その`mcp.json`エントリが`{"type": "registry"}`として宣言されている場合にのみ実行されます。レジストリ名と一致するものの、独自の`command`または`url`を指定しているエントリはスキップされます。`/mcp`パネルには、レジストリによって非表示にされた設定済みサーバーが一覧表示され、レジストリが提供するサーバーについては、その宣言方法が表示されます。`kiro-cli mcp list`は、これらのサーバーをアクティブではなく「スキップ済み」としてマークします。

レジストリに登録されている名前の`mcp.json`エントリは、依然として有用です。これは、APIキーやローカルパスなど、設定固有の値を指定するためのものです。「[レジストリサーバーのオーバーライド」](https://kiro.dev/docs/mcp/registry/#registry-server-overrides)を参照してください。

## レジストリによるサーバーのオーバーライド

レジストリモードが有効になっている場合でも、エージェントの設定または`mcp.json`ファイル（グローバル`~/.kiro/settings/mcp.json`またはワークスペース`.kiro/settings/mcp.json`）でレジストリのオーバーライドを使用して、サーバーをカスタマイズできます。 指定した値は、レジストリのデフォルト値に上書きされます。たとえば、レジストリで `NODE_ENV=development` が設定され、オーバーライドで `NODE_ENV=production` が設定されている場合、サーバーは `NODE_ENV=production` で実行されます。`env` および `headers` オブジェクトはキーごとにマージされるため、オーバーライドされていないレジストリのデフォルト値は保持されます。

json

```json
{
  "mcpServers": {
    "github": {
      "type": "registry",
      "env": {
        "GITHUB_TOKEN": "$GITHUB_TOKEN",
        "GITHUB_ORG": "my-org"
      },
      "timeout": 60000
    }
  }
}
```

上書き可能なフィールド:

- **ローカル (stdio) サーバー** - `env`（環境変数）、`timeout`（リクエストタイムアウト（ms））
- **リモート（HTTP）サーバー** - `headers`（HTTPヘッダー）、`timeout`（リクエストタイムアウト（ms））、`oauth`、および`oauthScopes`

レジストリタイプのエントリに対して定義した上書き設定は、起動されたサーバーに反映されるため、実行中のプロセスはカスタマイズされた値を使用します。

### リモートレジストリサーバー向けの OAuth

Kiro CLI V3 は、リモートサーバーに対して、組織レジストリから提供される `oauth` および `oauthScopes` の設定を使用します。ローカル環境では、対応するレジストリのオーバーライド設定によって、これらの値を置き換えることができます。これらのフィールドは、`mcp.json` のリモートサーバーと同じ形式を使用します。フィールドおよびスコープのルールについては、[「OAuth 認証」](https://kiro.dev/docs/mcp/configuration/#oauth-authentication)を参照してください。
