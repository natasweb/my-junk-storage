IAM Identity Center を利用している Pro ティアのお客様は、MCP レジストリを通じて MCP サーバーへのアクセスを制御することができます。管理者が設定を行うと、ユーザーはレジストリで明示的に許可された MCP サーバーのみを使用できるようになります。

**レジストリなし**（デフォルト）：

- ユーザーは任意のMCPサーバーを追加できます
- エージェントファイルまたはCLIで設定されたサーバー
- 一元的な制御なし

**レジストリあり**（エンタープライズ）：

- 管理者が許可されるサーバーを設定します
- ユーザーはレジストリのリストから選択します
- カスタムサーバーの追加は不可 — レジストリに登録されていないサーバーは非表示になります。これには、`mcp.json`で自身で定義したサーバーも含まれます
- 一元化されたガバナンスとセキュリティ

## レジストリサーバーの追加

レジストリモードでは、利用可能なサーバーがMCPパネルに表示されます。サーバーを選択して、構成に追加してください。

## レジストリに登録されていないサーバー

レジストリが有効になっている場合、実行可能なサーバーのソースはレジストリのみとなります。`mcp.json`（グローバル `~/.kiro/mcp.json` またはワークスペース `.kiro/mcp.json`）で定義したサーバーは、その名前がレジストリのエントリと一致する場合にのみ読み込まれます。それ以外のものはすべて非表示となり、レジストリが有効になる前に動作していたサーバーを含め、決して起動されることはありません。

IDE では、非表示のサーバーは個別のエントリとしてではなく、MCP パネルに「N 個のサーバーが非表示」という通知として表示されます。レジストリにないサーバーを実行するには、管理者に追加を依頼してください。

レジストリに登録されている`mcp.json`エントリは、依然として有用です。これは、APIキーやローカルパスなど、ご自身の環境に固有の値を指定するためのものです。「[レジストリによるサーバーのオーバーライド」](https://kiro.dev/docs/mcp/registry/#registry-server-overrides)を参照してください。

## レジストリによるサーバーのオーバーライド

レジストリモードが有効になっている場合でも、エージェントの設定または`mcp.json`ファイル（グローバル：`~/.kiro/mcp.json`、ワークスペース：`.kiro/mcp.json`）でレジストリのオーバーライドを使用してサーバーをカスタマイズできます。 指定した値はレジストリのデフォルト値に上書きされます。たとえば、レジストリで `NODE_ENV=development` が設定され、オーバーライドで `NODE_ENV=production` が設定されている場合、サーバーは `NODE_ENV=production` で実行されます。`env` および `headers` オブジェクトはキーごとにマージされるため、オーバーライドされていないレジストリのデフォルト値は保持されます。

json

```json
{
  "mcpServers": {
    "github": {
      "type": "registry",
      "env": {
        "GITHUB_TOKEN": "$GITHUB_TOKEN",
        "GITHUB_ORG": "my-org"
      },
      "timeout": 60000
    }
  }
}
```

上書き可能なフィールド:

- **ローカル（stdio）サーバー** - `env`（環境変数）、`timeout`（リクエストタイムアウト（ms））
- **リモート（HTTP）サーバー** - `headers`（HTTPヘッダー）、`timeout`（リクエストタイムアウト（ms））

レジストリ型エントリに対して定義した `env`、`headers`、および `timeout` の上書き設定は、起動されたサーバーに反映されるため、実行中のプロセスはカスタマイズされた値を使用します。
