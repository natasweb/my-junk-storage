クラウドセッションでは、[Kiroエージェントハーネス](https://kiro.dev/docs/how-kiro-works/)が、お使いのマシン上ではなく、管理されたクラウドサンドボックス内で実行されます。 このセッションは特定のアプリではなく、あなたのKiroアカウントに紐付いています。ブラウザでセッションを開始し、長時間かかるタスクを割り当て、ノートパソコンを閉じて、後でスマートフォン、ターミナル、またはIDEから状況を確認することも可能です。接続しているかどうかに関わらず、エージェントはサンドボックス内で動作し続けます。

クラウドセッションは、[Kiro](https://kiro.dev/docs/web/) WebおよびMobileの[背後にある](https://kiro.dev/docs/mobile/)実行環境であり、IDEやCLIから同じセッションを作成したり、そのセッションに接続したりすることができます。すべてのインターフェースが同じプロトコルを介して同じハーネスと通信するため、クラウドセッションは、サンドボックス上でファイル、ツール、設定を処理しながらも、Kiroのエージェントの中核となる動作を維持します。 主な違いは、作業が行われる場所です。クライアント固有の制限事項については、以下で説明します。

| 機能 | IDE | CLI | Web | モバイル |
| --- | --- | --- | --- | --- |
| クラウドセッションの作成 | ✓ | ✓ | ✓ | ✓ |
| 既存のクラウドセッションを再開および制御する | ✓ | ✓ | ✓ | ✓ |
| 自律モード | ✓ | ✓ | ✓ | ✓ |
| スケジュールされた[自動化](https://kiro.dev/docs/web/automations/) | — | — | ✓ | — |

## クラウドセッションの仕組み

クラウドセッションを作成すると、Kiroは隔離されたサンドボックスをプロビジョニングし、IDEやCLIでローカルに実行されるのと同じエージェントハーネスを起動します。リポジトリをアタッチすると、Kiroは接続済みのソースプロバイダーを介して**サーバー側で**それらをクローンします。ローカルの作業コピーがアップロードされることは一切ありません。 エージェントは、サンドボックス内で読み取り、編集、ビルド、およびシェルコマンドの実行を行い、その結果をソースプロバイダー経由（通常はプルリクエストとして）、または会話内で直接返します。

セッション自体は、どのクライアントからも独立したクラウドセッションストアに保存されます：

- **クライアントは接続・切断が可能です。**Webアプリ、モバイルアプリ、IDE、CLIはすべて、同じセッションへのビューです。クライアントの接続を切断してもエージェントは停止せず、実行中のタスクは継続して実行されます。
- **状態は端末を超えて保持されます：**会話履歴、紐付けられたリポジトリ、およびサンドボックス内のファイルの状態はクラウド上に永続化されます。どの端末からでも再接続すれば、会話記録は中断した箇所から再開されます。
- **承認はユーザーを待ちます：**誰も接続していない状態でエージェントがアクションの[許可](https://kiro.dev/docs/permissions/)を必要とした場合、そのリクエストは保留され、次に接続するクライアントに提示されます。

サンドボックス自体に関する詳細（ネットワークアクセス、環境変数、環境設定）については、[サンドボックスのドキュメント](https://kiro.dev/docs/web/sandbox/)を参照してください。

## 前提条件

- Pro、Pro+、Pro Max、または Power プランのサブスクリプション。クラウド セッションでは既存のクレジット モデルが適用され、クラウド コンピューティングに対する別途の課金は発生しません。
- リポジトリで作業する場合は、[GitHub](https://kiro.dev/docs/web/github/) または [GitLab](https://kiro.dev/docs/web/gitlab/) アカウントを接続しておく必要があります。
- AWS Identity Center 組織の場合：管理者は、Kiro が設定されている AWS アカウントの [**設定] > [Kiro 設定**] で **[Cloud Sessions]** をオンにして、Cloud Sessions を有効にする必要があります。詳細な手順については、[AWS Identity Center](https://kiro.dev/docs/web/identity-center/) を参照してください。Cloud Sessions は、**US East (N. Virginia)** の **`us-east-1`** でのみ実行されます
- 外部IDプロバイダー（IdP）としてOktaまたはMicrosoft Entra IDを使用している組織の場合：管理者は**Cloud Sessionsを**有効にし、既存のKiro OIDCアプリケーションに`https://app.kiro.dev/signin/oauth`を追加する必要があります。[OktaのリダイレクトURI設定またはMicrosoft](https://kiro.dev/docs/enterprise/identity-provider/okta/#create-new-app-integration) [Entra IDのリダイレクトURI設定](https://kiro.dev/docs/enterprise/identity-provider/microsoft-entra/#add-a-redirect-uri)の手順に従ってください

## クラウドセッションの操作

IDE では、クラウドセッションは[「エージェントフォーカスモード](https://kiro.dev/docs/ide/experimental/focus-mode/)」で利用できます。IDE ウィンドウの右上隅から「エージェントフォーカス」を開くと、セッションレールにローカルプロジェクトと並んで「**クラウドセッション**」セクションが表示されます。このセクションは、アカウントでクラウドセッションが利用可能な場合に表示されます。

### クラウドセッションを開始する

1. 「クラウド セッション」セクションのヘッダーにある**「+** (**新しいクラウド セッション**)」を選択します。これにより下書きが開きますが、この時点ではクラウド上にまだ何も作成されていません。
2. 必要に応じて、コンポーザーの下にある [**リポジトリを選択]** を選択し、接続済みのソースプロバイダーから 1 つ以上のリポジトリを紐付けます。選択されたリポジトリは、取り外し可能なピルとして表示されます。
3. モデル、エージェント、ワークフロー、および自律レベルを選択します。クラウドセッションでは「**オートパイロット」**と**「自律」**が利用可能です。「自律」を選択すると、操作モードとモデルの選択はエージェントに委ねられます。
4. 最初のプロンプトを入力して送信してください。Kiroがサンドボックスをプロビジョニングし、選択されたリポジトリをクローンして、プロンプトを送信します。セッションの設定中は、コンポーザーがロックされます。

セッションが開始されると、関連付けられたリポジトリがチャット入力欄の下に表示されたままになります。リポジトリはセッション作成時に選択されます。別のセットで作業するには、新しいクラウドセッションを開始してください。

### クラウドセッションの管理

クラウドセッションは、最近のアクティビティ順にサイドバーに表示され、ローカルセッションと同じステータスインジケーターが付いています。セッションのコンテキストメニューからは、以下の操作が可能です：

- **「セッションを固定**」：セッションをセクションの上部に固定します
- **「Kiro Webで開く」**を選択して、ブラウザで同じセッションを継続する
- **「Kiro CLIで開く」**：ターミナルから接続する（Kiro CLI 2.17以降が必要）
- **「セッションを削除**」：セッションとそのサンドボックスを完全に削除します

### ローカルセッションとは異なる動作

セッションのファイルはワークスペースではなくサンドボックス内に保存されるため、ローカルファイルに対して機能する操作はクラウドセッションでは利用できません。具体的には、エディタでのファイルや差分の開く操作、チェックポイントや元に戻す操作、`#File`/`#Folder`/`#Terminal`/`#Problems` のコンテキストピッカー、フック設定リンク、およびクリック可能な仕様タスクアクションなどが該当します。 プロンプトへの添付ファイル（画像やドキュメント）は機能し、その内容はセッションに送信されます。クラウドセッションの名前変更機能と「Supervised」モードは、まだ利用できません。

## どこで何が実行されるか

クラウドセッションは、お使いのマシンとサンドボックスの間に明確な境界線を引きます：

|  | ローカルマシン | クラウドサンドボックス |
| --- | --- | --- |
| プロンプトと添付ファイル | ここで作成 | セッションに送信されます（添付ファイルの内容はアップロードされます） |
| リポジトリのコード | アップロードされません | ソースプロバイダー接続を介してサーバー側でクローン化 |
| エージェントによるファイルの読み取りおよび編集 | — | サンドボックス内で実行 |
| シェルコマンドおよびビルド | — | サンドボックス内で実行 |
| プロジェクト設定（リポジトリ内の `.kiro/`） | — | リポジトリのクローンとともに提供される |
| ローカルの個人設定（`~/.kiro/`） | ローカルに保持される | 適用されません。サポートされているアカウント関連の項目については、個人のクラウド設定を使用してください |

## クラウド上の設定

クラウドセッションとパーソナルクラウド設定は、アカウントに紐づく機能として関連していますが、その目的は異なります。クラウドセッションは、エージェントが動作する場所を決定します。パーソナルクラウド設定は、Kiroがサポート対象のインターフェース全体でどのアカウントレベルの設定を利用可能にするかを決定します。

設定の[適用範囲](https://kiro.dev/docs/configuration/)は他の場所と同様です：

- **プロジェクト設定はリポジトリと共に移動します。**リポジトリ内の ``.kiro/`` ディレクトリ下にコミットされたステアリング、仕様、カスタムエージェント、フック、および MCP サーバーは、サンドボックスがリポジトリをクローンするため、クラウドセッションで自動的に適用されます。
- **個人設定はアカウントを通じて同期できます。**ローカルの ``~/.kiro/`` ディレクトリはローカルに留まり、クラウドセッションには適用されません。[Kiro Web](https://app.kiro.dev/settings/cloud-config) の **[設定] > [設定の同期]** を使用して、サポートされている個人設定をアップロードしてください。クラウド上のコピーは、機能ごとの設定ページ（**[設定] > [Powers]** 内のアカウントベースの [Powers](https://kiro.dev/docs/powers/) を含む）から管理します。サポートされているフォルダとアップロードのワークフローについては、[「設定の同期」](https://kiro.dev/docs/web/cloud-configuration/)を参照してください。
- **サンドボックス環境：**インターネットアクセス、環境変数、およびセットアップコマンドについては、[サンドボックスのドキュメントで](https://kiro.dev/docs/web/sandbox/)説明されています。

### IDEでの個人用クラウド設定の使用

アカウントで個人用クラウド設定が有効化されており、クラウド管理対象の項目が提供されている場合、Kiro IDE 1.0.437 以降では、個人用ステアリング、カスタムエージェント、スキル、パワーズ、フックが通常の IDE 画面に表示されます。 クラウドインジケーターは、Kiro Webで管理されている項目を示します。Cloud Steering、Skills、およびHooksは、「**Webで編集**」アクション付きの読み取り専用プレビューとして開きます。エージェントフォーカスの設定には、同じクラウドソースと、Kiro Webでそれらの項目を管理するためのリンクが表示されます。

クラウド設定が有効になっているものの、アカウントにクラウドアイテムが存在しない場合、これらのインジケーターや管理アクションは表示されず、IDEの画面は変更されません。

IDEの個人用クラウド設定画面には、スタンドアロンのMCPサーバーは含まれません。設定の同期機能はMCPサーバーの設定を個別に処理します。つまり、「`settings/mcp.json`」をアップロードすると、それらのサーバーはクラウド管理下のMCPサーバーとしてIDEに送信されるのではなく、Kiro WebのサンドボックスMCPサーバー設定に送信されます。 これは、[Power](https://kiro.dev/docs/powers/) にバンドルされている MCP 構成とも異なります。バンドルされた MCP 構成はその Power に属し、Power がアクティブなときに利用可能になります。`.kiro/` でコミットされたプロジェクトレベルの MCP サーバーは、引き続きプロジェクトの構成スコープに従います。

## サーフェス間の移動

クラウドセッションは、どのアプリを通じて表示しても、1つのセッションとして扱われます：

| 元 | から | 方法 |
| --- | --- | --- |
| Webまたはモバイル | CLI | `kiro-cli --resume-id <session-id>` |
| IDE（エージェント向け） | Web | **Kiro Webの**セッションメニューから**開く** |
| IDE（エージェント重視） | CLI | セッションメニューから **Kiro CLI で開く** |
| CLI | Web | `app.kiro.dev` でセッションを開く |
| 任意 | モバイル | セッションがモバイルアプリのセッション一覧に表示されます |

## 現在の制限事項

- **同時実行数の制限：**最大 10 個のクラウド セッションを並行して実行できます。
- **リポジトリセットは固定されています：**セッション作成時にリポジトリを選択します（CLI を使用すれば、後で ``/repo`` コマンドで追加することも可能です）。別のリポジトリで作業するには、新しいセッションを開始してください。
- **スーパーバイズドモードなし：**クラウドセッションは「オートパイロット」または「自律」モードで実行されます。変更ごとの承認機能は利用できません。
- **名前の変更不可：**IDE や CLI からクラウド セッションの名前を変更することはできません。
- **機能の未対応箇所：**上記の各タブには、クラウドセッションではまだ機能しないコマンドや操作がリストされています。これらの未対応箇所は、インターフェースやリリースによって異なる場合があります。
