クラウドセッションでは、[Kiroエージェントハーネス](https://kiro.dev/docs/how-kiro-works/)を、お使いのマシン上ではなく、管理されたクラウドサンドボックス上で実行します。 このセッションは特定のアプリではなく、あなたのKiroアカウントに紐付いています。ブラウザで起動し、長時間かかるタスクを割り当て、ノートパソコンを閉じて、後でスマートフォン、ターミナル、またはIDEから状況を確認することも可能です。接続しているかどうかに関わらず、エージェントはサンドボックス内で動作し続けます。

クラウドセッションは、[Kiro Web](https://kiro.dev/docs/web/)およびMobileの背後[にある](https://kiro.dev/docs/mobile/)実行環境であり、IDEやCLIから同じセッションを作成したり、接続したりすることができます。すべてのインターフェースが同じプロトコルを介して同じハーネスと通信するため、クラウドセッションは、サンドボックスでサポートされるファイル、ツール、設定に対して実行される際も、Kiroのエージェントの中核となる動作を維持します。 主な違いは、作業が行われる場所です。クライアント固有の制限については、以下で説明します。

| 機能 | IDE | CLI | Web | モバイル |
| --- | --- | --- | --- | --- |
| クラウドセッションの作成 | ✓ | ✓ | ✓ | ✓ |
| 既存のクラウドセッションを再開・制御する | ✓ | ✓ | ✓ | ✓ |
| 自律モード | ✓ | ✓ | ✓ | ✓ |
| 宣言型[ワークフロー](https://kiro.dev/docs/workflows/) | ✓ | ✓ | ✓ | 未記載 |
| [スケジュールされたタスク](https://kiro.dev/docs/web/automations/) | — | — | ✓ | — |

## クラウドセッションの仕組み

クラウドセッションを作成すると、Kiroは隔離されたサンドボックスをプロビジョニングし、IDEやCLIでローカルに実行されるのと同じエージェントハーネスを起動します。リポジトリをアタッチすると、Kiroは接続されたソースプロバイダーを通じて**サーバー側で**それらをクローンします。ローカルの作業コピーがアップロードされることは一切ありません。 エージェントは、サンドボックス内で読み取り、編集、ビルド、およびシェルコマンドの実行を行い、その結果をソースプロバイダー経由（通常はプルリクエストとして）または会話画面に直接返します。

セッション自体は、どのクライアントからも独立したクラウドセッションストアに保存されます：

- **クライアントは接続・切断が可能です。**Webアプリ、モバイルアプリ、IDE、CLIはすべて、同じセッションへのビューです。クライアントの接続を切断してもエージェントは停止せず、実行中のタスクは継続して実行されます。
- **状態は端末を超えて保持されます：**会話履歴、紐付けられたリポジトリ、およびサンドボックスのファイル状態はクラウド上に永続化されます。どの端末からでも再接続すれば、会話記録は中断した箇所から再開されます。
- **承認はユーザーを待ちます：**誰も接続していない状態でエージェントがアクションの[許可](https://kiro.dev/docs/permissions/)を必要とした場合、そのリクエストは保留され、次に接続するクライアントに提示されます。
- **ワークフローは親セッション内で実行可能です：**宣言型[ワークフロー](https://kiro.dev/docs/workflows/)は、クラウド上の親会話が利用可能な状態である限り、独自のネストされたステップセッションと永続的なグラフを維持します。進行状況と結果は、その親セッションに返されます。

サンドボックス自体に関する詳細（ネットワークアクセス、環境変数、環境設定）については、[サンドボックスのドキュメント](https://kiro.dev/docs/web/sandbox/)を参照してください。

## 前提条件

- Pro、Pro+、Pro Max、または Power サブスクリプション。クラウド セッションは既存のクレジット モデルを使用し、クラウド コンピューティングに対する別途の課金は発生しません。
- リポジトリで作業する場合は、接続済みの [GitHub](https://kiro.dev/docs/web/github/) または [GitLab](https://kiro.dev/docs/web/gitlab/) アカウントが必要です
- AWS Identity Center 組織の場合：管理者は、Kiro が設定されている AWS アカウントの [**設定] > [Kiro 設定]** で**「Cloud Sessions」**をオンに切り替えて、Cloud Sessions を有効にする必要があります。詳細な手順については、[AWS Identity Center](https://kiro.dev/docs/web/identity-center/) を参照してください。Cloud Sessions は、**US East (N. Virginia) `us-east-1`** でのみ実行されます
- 外部IDプロバイダー（IdP）としてOktaまたはMicrosoft Entra IDを使用している組織の場合：管理者は、**Cloud Sessions**を有効にし、既存のKiro OIDCアプリケーションに`https://app.kiro.dev/signin/oauth`を追加する必要があります。[OktaのリダイレクトURI設定またはMicrosoft](https://kiro.dev/docs/enterprise/identity-provider/okta/#create-new-app-integration) [Entra IDのリダイレクトURI設定](https://kiro.dev/docs/enterprise/identity-provider/microsoft-entra/#add-a-redirect-uri)の手順に従ってください

## クラウドセッションの操作

IDE では、クラウドセッションは[「エージェントフォーカスモード](https://kiro.dev/docs/ide/experimental/focus-mode/)」で利用できます。IDE ウィンドウの右上隅から「エージェントフォーカス」を開くと、セッションレールにローカルプロジェクトと並んで「**クラウドセッション**」セクションが表示されます。このセクションは、アカウントでクラウドセッションが利用可能な場合に表示されます。

### クラウドセッションの開始

1. 「クラウド セッション」セクションのヘッダーにある**「+** (**新しいクラウド セッション**)」を選択します。これにより下書きが開きますが、この時点ではクラウド上に何も作成されていません。
2. 必要に応じて、コンポーザーの下にある [**リポジトリを選択]** を選択し、接続済みのソースプロバイダーから1つ以上のリポジトリを関連付けます。選択されたリポジトリは、取り外し可能なピルとして表示されます。
3. モデル、エージェント、ワークフロー、および自律レベルを選択します。クラウドセッションでは「**オートパイロット」**と**「自律」**が利用可能です。「自律」を選択すると、操作モードとモデルの選択はエージェントに委ねられます。
4. 最初のプロンプトを入力して送信します。Kiroがサンドボックスをプロビジョニングし、選択されたリポジトリをクローンして、プロンプトを送信します。セッションのセットアップ中は、コンポーザーがロックされます。

セッションが開始されると、関連付けられたリポジトリがチャット入力欄の下に表示されたままになります。リポジトリはセッション作成時に選択されます。別のセットで作業するには、新しいクラウドセッションを開始してください。

### クラウドセッションの管理

クラウドセッションは、最近のアクティビティ順にサイドバーに表示され、ローカルセッションと同じステータスインジケーターが表示されます。セッションのコンテキストメニューから、以下の操作が可能です：

- **「セッションを固定**」：セッションをセクションの上部に固定します
- **「Kiro Webで開く」**を選択して、ブラウザで同じセッションを継続する
- **「Kiro CLIで開く」**を選択して、ターミナルから接続する（Kiro CLI 2.17以降が必要）
- **「セッションを削除**」：セッションとそのサンドボックスを完全に削除します

### ローカルセッションとは異なる動作

セッションのファイルはワークスペースではなくサンドボックス内に保存されるため、ローカルファイルに対して機能する操作はクラウドセッションでは利用できません。具体的には、エディタでのファイルや差分の開く操作、チェックポイントや元に戻す操作、`#File`／`#Folder`／`#Terminal`／`#Problems`のコンテキストピッカー、フック設定リンク、およびクリック可能な仕様タスクアクションなどが該当します。 プロンプトの添付ファイル（画像やドキュメント）は機能し、その内容はセッションに送信されます。クラウドセッションの名前変更および「Supervised」モードは、現時点では利用できません。

## どこで何が実行されるか

クラウドセッションでは、お使いのマシンとサンドボックスの間に明確な境界が設けられています：

|  | ローカルマシン | クラウドサンドボックス |
| --- | --- | --- |
| プロンプトと添付ファイル | ここで作成 | セッションに送信されます（添付ファイルの内容はアップロードされます） |
| リポジトリのコード | アップロードされません | ソースプロバイダー接続を介してサーバー側でクローン化 |
| エージェントによるファイルの読み取りおよび編集 | — | サンドボックス内で実行 |
| シェルコマンドおよびビルド | — | サンドボックス内で実行 |
| プロジェクト設定（リポジトリ内の`.kiro/`） | — | リポジトリのクローンとともに取得される |
| ローカルの個人設定（`~/.kiro/`） | ローカルに保持される | 適用されません。サポートされているアカウント関連の項目については、個人のクラウド設定を使用してください |

## クラウド上の設定

クラウドセッションと個人用クラウド設定は、アカウントに紐づく機能として関連していますが、その目的は異なります。クラウドセッションは、エージェントが動作する場所を決定します。個人用クラウド設定は、Kiroがサポート対象のインターフェース全体でどのアカウントレベルの設定を利用可能にするかを決定します。

設定の[適用範囲](https://kiro.dev/docs/configuration/)は他の場所と同様です：

- **プロジェクト設定はリポジトリと共に移動します。**リポジトリ内の`.kiro/`の下にコミットされたステアリング、仕様、カスタムエージェント、フック、およびMCPサーバーは、サンドボックスがリポジトリをクローンするため、クラウドセッションで自動的に適用されます。
- **個人設定はアカウントを通じて同期できます。**ローカルの`~/.kiro/`ディレクトリはローカルに留まり、クラウドセッションには適用されません。 [Kiro Web](https://app.kiro.dev/settings/cloud-config) の **[Agent Config] > [Cloud Config]** を使用して、サポートされている個人設定をアップロードします。クラウド上のコピーは、機能ごとの設定ページ（**[Agent Config] > [Powers & MCP]** 内のアカウントベースの [Powers](https://kiro.dev/docs/powers/) を含む）から管理します。サポートされているフォルダおよびアップロードのワークフローについては、[「設定の同期」](https://kiro.dev/docs/web/cloud-configuration/)を参照してください。
- **サンドボックス環境：**インターネットアクセス、環境変数、およびセットアップコマンドについては、[サンドボックスのドキュメントで](https://kiro.dev/docs/web/sandbox/)説明されています。

### IDE での個人用クラウド設定の使用

アカウントで個人用クラウド設定が有効化されており、クラウド管理対象の項目が提供されている場合、Kiro IDE 1.0.437 以降では、個人用ステアリング、カスタムエージェント、スキル、パワーズ、フックが通常の IDE 画面に表示されます。 クラウドインジケーターは、Kiro Web で管理されている項目を示します。クラウド・ステアリング、スキル、およびフックは、読み取り専用のプレビューとして開き、「**Web で編集**」アクションが表示されます。エージェント・フォーカスの設定には、同じクラウドソースと、Kiro Web でそれらの項目を管理するためのリンクが表示されます。

クラウド設定が有効になっているものの、アカウントにクラウドアイテムが存在しない場合、これらのインジケーターや管理アクションは表示されず、IDEの画面は変更されません。

IDEの個人用クラウド設定画面には、スタンドアロンのMCPサーバーは含まれません。設定の同期機能はMCPサーバーの設定を個別に処理します。`settings/mcp.json`をアップロードすると、それらのサーバーは「**エージェント設定 > パワーとMCP**」（MCPサーバー設定）に送信され、クラウド管理下のMCPサーバーとしてIDEには送信されません。 これは、[Power](https://kiro.dev/docs/powers/) にバンドルされている MCP 構成とも異なります。バンドルされた MCP 構成はその Power に属し、Power がアクティブになったときに利用可能になります。`.kiro/` でコミットされたプロジェクトレベルの MCP サーバーは、引き続きプロジェクトの構成スコープに従います。

## サーフェス間の移動

クラウドセッションは、どのアプリを通じて表示しても、1つのセッションとして扱われます：

| 元 | から | 方法 |
| --- | --- | --- |
| Webまたはモバイル | CLI | `kiro-cli --resume-id <session-id>` |
| IDE（エージェント向け） | Web | **Kiro Webの**セッションメニューから**開く** |
| IDE（エージェント重視） | CLI | セッションのメニューから **Kiro CLI で開く** |
| CLI | Web | `app.kiro.dev` でセッションを開く |
| 任意 | モバイル | セッションがモバイルアプリのセッション一覧に表示されます |

## 現在の制限事項

- **同時実行数の制限：**最大 10 個のクラウド セッションを並行して実行できます。
- **スーパーバイズドモードなし：**クラウドセッションは「オートパイロット」または「自律」モードで実行されます。変更ごとの承認機能は利用できません。
- **名前の変更不可：**IDE や CLI からクラウド セッションの名前を変更することはできません。
- **インターフェース上の機能制限：**上記の各タブには、クラウドセッションではまだ機能しないコマンドや操作がリストされています。これらの機能制限は、インターフェースやリリースによって異なる場合があります。
