エージェントとのセッションは試行錯誤の連続です。エージェントが誤った方向に進んでしまったり、これまでの成果を失うことなく別のアプローチを試してみたい場合もあるでしょう。Kiroでは、元に戻るための2つの異なる方法が用意されています。**チェックポイントを使用すると**、ファイルをセッションの以前の時点に復元でき、**リワインドを使用すると**、会話の分岐点を以前の分岐点まで巻き戻すことができます。

## チェックポイントと巻き戻しの比較

これら2つの仕組みは、それぞれ異なる問題を解決します：

- **チェックポイントは、**エージェントがファイルを変更するたびにそのスナップショットを保存します。チェックポイントを復元すると、ワークスペースがその時点の状態にロールバックされ、それに伴って会話のコンテキストも巻き戻されるため、エージェントの理解が復元されたファイルの状態と一致するようになります。
- **巻き戻し（Rewind）は**ファイルには一切触れません。以前のターンで会話を分岐させて新しいセッションを作成し、元のセッションとディスク上のファイルはそのままの状態を維持します。

**エージェントの作業を元**に戻したい場合はチェックポイントを使用します。これまでのファイルの変更を維持したまま、**会話の方向性を**変えたい場合（例えば、同じ出発点から別のプロンプトを試したい場合など）には、リワインドを使用します。

## チェックポイントとリワインドの使用

Kiroにプロンプトを送信するたびに、チェックポイントが作成されます。 チェックポイントはチャット履歴上にマーカーとして表示されます。チェックポイントマーカーの **[復元]** を選択すると、コードベースと Kiro のコンテキストの両方がその時点まで巻き戻されます。そのチェックポイント以降に Kiro によってコードベースに加えられた変更はすべて元に戻され、その時点以降のコンテキストへの追加（チャットのやり取り）も破棄されます。

チェックポイントはセーフティネットとして機能し、問題に対する複数のアプローチを自信を持って模索したり、特定のタスクに対して異なるモデルを試したり、エージェントによるミスや誤解から回復したりすることを可能にします。

### チェックポイントが追跡する内容

チェックポイントは、Kiroエージェントが組み込みのファイル編集ツールを使用してファイルを変更するたびに、そのファイルの内容をスナップショットとして保存し、そのチェックポイントに巻き戻す際にそのスナップショットを復元することで機能します。

Kiroは、Kiroエージェント*の外*で行われたファイルへの変更は追跡しません。 Kiroがファイルのスナップショットを作成した後、その同じファイルを手動で編集したり、コードフォーマットツールを実行したりした場合、そのチェックポイントにロールバックすると、変更内容は失われます。また、Kiroは、実行の一環として実行されるMCPツールやbashコマンドによるファイルの変更も追跡しません。

### リバートとチェックポイント

Kiroエージェントが1つ以上のファイルを変更してターンを完了するたびに、チャット入力ボックスのすぐ上に、エージェントによる変更を**「リバート」**するオプションが表示されます。

「元に戻す」はチェックポイントと似ていますが、2つの重要な点で異なります。第一に、「元に戻す」はエージェントの*直近*のターンで行われた変更のみを元に戻すのに対し、チェックポイントは複数のターンにわたる変更を元に戻すことができます。第二に、「元に戻す」は*ファイルの*変更のみを元に戻すのに対し、チェックポイントはファイルの変更に加え、チェックポイント以降に追加されたコンテキストも破棄します。
