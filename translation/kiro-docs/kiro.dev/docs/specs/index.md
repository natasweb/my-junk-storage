## 仕様とは何ですか？

仕様（Specs）とは、アプリケーションの機能開発やバグ修正のプロセスを体系化した文書です。これらは、大まかなアイデアを、明確な進捗管理と責任の所在が明確な詳細な実装計画へと変換するための体系的なアプローチを提供します。

| 機能 | IDE | CLI | Web | モバイル |
| --- | --- | --- | --- | --- |
| 機能仕様 | ✓ | ✓ | ✓ | — |
| バグ修正仕様 | ✓ | ✓ | ✓ | — |
| 概要仕様 | ✓ | ✓ | ✓ | — |
| 並列タスク実行 | ✓ | ✓ | ✓ | — |
| [要件の分析](https://kiro.dev/docs/specs/analyze-requirements/) | ✓ | ✓ | — | — |
| [正しさ](https://kiro.dev/docs/specs/correctness/)（プロパティベーステスト） | ✓ | — | — | — |

Kiroの仕様書を使えば、以下のことが可能です：

- **要件を、**受け入れ基準付きのユーザーストーリーに**分解する**
- シーケンス図やアーキテクチャ計画を含む**設計ドキュメントを作成する**
- 個別のタスクにわたる**実装の進捗を追跡する**
- プロダクトチームとエンジニアリングチーム間で**効果的に連携する**

## 基本構成

各仕様書には、仕様の基盤となる3つの主要ファイルが生成されます：

- **requirements.md**（またはbug**fix.md**） - ユーザーストーリー、受け入れ基準、またはバグ分析を構造化された表記で記述します
- **design.md** - 技術アーキテクチャ、シーケンス図、および実装上の考慮事項を文書化します
- **tasks.md** - 個別の追跡可能なタスクを含む詳細な実装計画を提供します

## 3段階のワークフロー

すべての仕様書は、アイデアを実行可能な実装へと変換する3段階のワークフローに従います：

**要件またはバグ分析** - 構築または修正すべき内容を定義します

- 機能仕様：`requirements.md` 内のユーザーストーリーおよび受け入れ基準
- バグ修正仕様：`bugfix.md` 内の、現在の動作・期待される動作・変更されない動作を含むバグ分析

**設計** — `design.md` での技術アーキテクチャおよび実装アプローチの策定

- システムアーキテクチャおよびコンポーネント設計
- シーケンス図とデータフロー
- エラー処理とテスト戦略

**タスク** - `tasks.md` における、個別の実行可能な実装タスクの生成

- 明確な成果が定義された追跡可能なタスク
- 実装中のリアルタイムな進捗状況の更新
- タスクを個別に、またはまとめて実行

## タスクの実行

Kiroは、`tasks.md`ファイル用のタスク実行インターフェースを提供し、リアルタイムのステータス更新を表示します。タスクは「進行中」または「完了」として更新されるため、実装の進捗を効率的に追跡できます。

[](/videos/spec-task.mp4?h=66bfe3fb)

### タスクの並列実行

仕様書上のすべてのタスクを実行する際、Kiroはタスクリストを分析し、どのタスクが互いに依存しているかを特定した上で、独立したタスクを並行して実行します。ほとんどの機能仕様書において、これにより特別な設定を必要とせずに実行時間を大幅に短縮できます。

Kiroは、`tasks.md`内のタスクの**依存関係グラフ**を構築し、独立したタスクを**ウェーブ**ごとにグループ化します：

- **Wave 1** - 依存関係のないすべてのタスク。これらは並行して実行されます。
- **ウェーブ 2** - ウェーブ 1 によって依存関係が満たされたすべてのタスク。これらは並行して実行されます。
- **ウェーブ N** — すべてのタスクが完了するまで続行されます。

ウェーブは順次実行され、各ウェーブ内のタスクは並行して実行されます。

## 仕様の種類

Kiroでは、開発のニーズに合わせて2種類の仕様をサポートしています：

### 機能仕様

アプリケーションに新しい機能や能力を構築するためのものです。機能仕様書は、「要件ファースト」と「設計ファースト」という2つのワークフローバリエーションを通じて、要件収集、技術設計、実装計画のプロセスをガイドします。十分に理解されている機能については、[「クイック仕様書」](https://kiro.dev/docs/specs/quick-spec/)を使用して、承認プロセスを経ずにこれら3つの成果物をすべて自動生成することも可能です。

[機能仕様の詳細はこちら →](https://kiro.dev/docs/specs/feature-specs/)

### バグ修正仕様

バグを体系的に診断し、回帰を防止しながら極めて精密に修正するためのものです。バグ修正仕様書は、根本原因の特定、修正案の設計、および他の部分に不具合が生じていないことの検証を支援します。

[Bugfix Specsの詳細はこちら →](https://kiro.dev/docs/specs/bugfix-specs/)

## はじめに

1. Kiroペインの「**Specs**」の下にある「`+`」ボタンをクリックします。または、チャットペインから**「Spec」**を選択します。
2. Kiroから、「機能の開発」か「バグ
   の修正」のどちらを行うか尋ねられます
   - 「機能」を選択した場合は、その機能の概要を説明し、ワークフローとして「**要件ファースト**」または「**設計ファースト**」のいずれかを選択してください
   - 「Bug」を選択した場合は、バグの内容を説明してください
3. 各フェーズを経て、実装に至るまでワークフローに従ってください
