要件から設計に移る前に、Kiroに依頼して、要件に含まれる論理的な矛盾、曖昧さ、および抜け漏れを分析してもらうことができます。この詳細な分析では、個々の要件を単独で検討するのではなく、要件セット全体を包括的に検討することで、単に読み通すだけでは見つけにくい問題点を洗い出します。

## 検出可能な問題

- **論理的な矛盾** — 個々に見れば理にかなっているが、組み合わせると実現不可能な2つの要件
- **曖昧さ** — 「大容量のファイル」や「高速な応答時間」といった、実装方法にばらつきを生じさせる表現
- **矛盾する制約** — 機能要件と非機能要件のすべてを同時に満たすことができない場合
- **明示されていない前提** — 定義されていない概念や挙動への言及
- **見落とされたエッジケース** — ハッピーパスではカバーされていない障害モード、境界条件、および並行アクセスシナリオ

## 呼び出し方法

要件が生成されると、「**要件の分析」**というオプションが以下の2か所に表示されます：

- チャット画面で、次の手順に関する他のオプションと並んで表示されます
- エディタの [続行] ドロップダウンメニュー内、「**設計へ進む」**の横

## 結果の概要

分析には数秒ではなく数分かかります。要件間の相互関係に基づく推論は、通常の Kiro 操作よりも計算負荷が高いためです。分析結果がまとまり次第、質問がチャットに表示されます。

各質問には、関連する要件、問題点の平易な説明、および選択可能な修正案が含まれています。また、曖昧さが意図的な場合は、独自の回答を入力したり、質問を却下したりすることもできます。質問を解決するにつれて、Kiroはエディタ内の「`requirements.md`」を更新します。

## 使用すべき場面

この分析は、要件数が多い複雑な機能、ドメイン固有のプロジェクト（金融サービス、医療、コンプライアンス）、および手動によるレビューなしに要件が自動生成された「[Quick Spec](https://kiro.dev/docs/specs/quick-spec/)」セッションにおいて特に有用です。小規模な仕様や十分に理解されている仕様については、分析をスキップして直接設計に進むことができます。

要件を手動で編集した後でも、分析を再実行できます。Kiroは、影響を受ける要件とその相互作用を再分析します。
