エージェントフックは、特定の自動化シナリオに合わせて設計されたさまざまなトリガータイプに対応しています。これらのタイプを理解することで、ワークフローのニーズに合った適切なアプローチを選択できるようになります。

## プロンプトの送信

ユーザーがプロンプトを送信したときにトリガーされます。

シェルコマンドアクションを使用する場合、ユーザープロンプトには`USER_PROMPT`環境変数を通じてアクセスできます。

**使用例：**

- プロンプトに関連する追加のコンテキストをエージェントに提供
- 内容に基づいて特定のプロンプトをブロックする
- すべてのユーザープロンプトを一元的な場所に記録する

## エージェントの停止

エージェントが自分のターンを完了し、ユーザーへの応答を終えたときにトリガーされます。

これは、エージェントの応答後に、コードのコンパイル、テスト、フォーマット、クリーンアップなどの後処理タスクを実行するのに役立ちます。

**ユースケース：**

- コードをコンパイルし、失敗した場合はエージェントに報告する
- エージェントが生成したコードのフォーマットやレビューを行う
- エージェントによる変更内容をレビューし、追加の指示を出す

## セッション開始（IDEのみ）

IDEで新しいチャットセッションが開始されたときにトリガーされます。

**ユースケース：**

- エージェントのコンテキストにワークスペース固有の指示を挿入する
- 環境チェックを実行する（依存関係の確認、認証情報の検証）
- セッション開始時にプロジェクト固有の設定を読み込む

## エージェントの起動（CLIのみ）

エージェントが最初に起動されたときに実行されます。ツールコンテキストは提供されません。

json

```json
{
  "hook_event_name": "agentSpawn",
  "cwd": "/current/working/directory",
  "session_id": "abc123-def456-789"
}
```

**終了コードによる動作:**

- **0**: フックが成功し、STDOUTがエージェントのコンテキストに追加される
- **その他**: ユーザーに STDERR 警告を表示する

**ユースケース:**

- セッション開始時に環境コンテキストを設定する
- プロジェクト固有の設定を読み込む
- ロギングまたは監査システムの初期化

## ツール使用前

エージェントがツールを呼び出そうとする際にトリガーされます。ツールの使用を検証し、ブロックすることができます。

[**ツール名**] フィールドに、このフックを実行すべき特定のツールの名前を指定します。複数のエントリを指定できます。以下の組み込みカテゴリがサポートされています：

- **read** - すべての組み込みファイル読み取りツール
- **write** - すべての組み込みファイル書き込みツール
- **shell** - すべての組み込みシェルコマンド関連ツール
- **web** - すべての組み込みWebツール
- **spec** - すべての組み込み spec ツール
- ***** - すべてのツール（組み込みおよびMCP）

また、プレフィックスフィルターを使用して、ソース別にツールを指定することもできます:

- **@mcp** - すべての MCP ツール
- **@powers** - すべての Powers ツール
- **@builtin** - すべての組み込みツール

`@` で始まるプレフィックスは正規表現でマッチするため、`@mcp.*sql.*` のようなパターンを使用して、特定の MCP ツールを名前で指定することができます。

利用可能なツールの名前については、Kiroに問い合わせることができます。

**使用例：**

- 特定のツールの実行をブロックする
- 実行前にツールの入力内容を検証する
- エージェントがツールを呼び出す前に追加の指示を与える

## ツール使用後

エージェントがツールを呼び出した後にトリガーされ、ツールの結果にアクセスできます。

「**ツール名」**フィールドの詳細については、上記の「[ツール使用前」](https://kiro.dev/docs/hooks/types/#pre-tool-use)セクションを参照してください。

**ユースケース：**

- 監査目的でツールの呼び出しを記録する
- 「書き込み」ツールの呼び出し後に、更新されたファイルのフォーマット調整や確認を行う
- ツールの応答に加えて、エージェントに追加の指示を提供する

## ファイル作成

エージェントがワークスペース内で特定のパターンに一致する新しいファイルを作成した際にトリガーされます。

**ユースケース：**

- 新しいコンポーネント用の定型コードを生成する
- 新しいファイルにライセンスヘッダーを追加する
- 実装ファイルの作成時にテストファイルを設定する

## ファイルの保存

エージェントが特定のパターンに一致するファイルを保存または変更した際にトリガーされます。

**ユースケース:**

- リンティングとフォーマットを実行する
- 関連ファイルの更新
- ドキュメントを生成する
- 変更されたファイルのテストを実行する

## ファイルの削除

エージェントが特定のパターンに一致するファイルを削除したときにトリガーされます。

**ユースケース：**

- 関連ファイルの整理
- 他のファイル内のインポート参照を更新する
- プロジェクトの整合性を維持する

## タスク実行前（IDEのみ）

仕様タスクの実行が開始される前、そのステータスが「in_progress」に変わった際にトリガーされます。

**ユースケース：**

- タスク実行前にセットアップスクリプトを実行したり、環境の準備を行ったりする
- タスク開始前に前提条件が満たされていることを検証する
- 追跡のためにタスク開始イベントをログに記録する

## タスク実行後（IDEのみ）

特定のタスクの実行が完了し、ステータスが「完了」に変わった後にトリガーされます。

**ユースケース：**

- タスク完了後にテストを実行し、正しさを検証する
- 変更されたファイルに対してリンティングやフォーマット処理を実行する
- 完了した作業のドキュメントを生成する
- タスクの完了を外部システムに通知する

## レガシー手動フック（IDEのみ）

IDE 0.x で作成された手動フックは、「**レガシー」**というラベルが付いた状態で、引き続き「エージェントフック」パネルに表示されます。有効になっているレガシー手動フックは、フック名の横にある再生ボタン、またはフックビューの「`Start Hook`」を使用して実行可能です。

レガシー手動フックには v1 トリガーに相当するものはなく、新しい「手動トリガー」フックを作成することはできません。新しいオンデマンドワークフローについては、[手動で含めるステアリングファイル](https://kiro.dev/docs/steering/#manual-inclusion)を作成してください。これは、`/<filename>` のスラッシュコマンドとして実行されます。

## MCP ツールフック

MCP ツールの場合、ツール名には MCP サーバー名を含む完全な名前空間形式が含まれます:

json

```json
{
  "hook_event_name": "preToolUse",
  "cwd": "/current/working/directory",
  "session_id": "abc123-def456-789",
  "tool_name": "@postgres/query",
  "tool_input": {
    "sql": "SELECT * FROM orders LIMIT 10;"
  }
}
```

これは、MCP サーバーのツールを対象とする「ツール使用前」および「ツール使用後」の両方のフックに適用されます。
