## プロンプトの送信

ユーザーがプロンプトを送信したときにトリガーされます。

シェルコマンドアクションを使用する場合、ユーザープロンプトには`USER_PROMPT`環境変数を通じてアクセスできます。

**使用例：**

- プロンプトに関連する追加のコンテキストをエージェントに提供
- 内容に基づいて特定のプロンプトをブロックする
- すべてのユーザープロンプトを一元的な場所に記録する

## エージェントの停止

エージェントが自分のターンを完了し、ユーザーへの応答を終えたときにトリガーされます。

これは、エージェントの応答後に、コードのコンパイル、テスト、フォーマット、クリーンアップなどの後処理タスクを実行するのに役立ちます。

**ユースケース：**

- コードをコンパイルし、失敗した場合はエージェントに報告する
- エージェントが生成したコードのフォーマットやレビューを行う
- エージェントによる変更内容をレビューし、追加の指示を出す

## セッション開始

IDEまたはCLI V3で新しいチャットセッションが開始されたときにトリガーされます。CLI V3では、標準の`SessionStart`トリガーを使用してください。

**ユースケース：**

- エージェントのコンテキストにワークスペース固有の指示を挿入する
- 環境チェックを実行する（依存関係の確認、認証情報の検証）
- セッション開始時にプロジェクト固有の設定を読み込む

## エージェントの起動

CLI 2.x では、エージェントが最初にアクティブ化された際に ``agentSpawn`` が実行されます。CLI V3 では、標準的なトリガーとして ``SessionStart`` を使用しますが、互換性のため ``AgentSpawn`` および ``agentSpawn`` も受け付けます。ツールコンテキストは提供されません。

json

```json
{
  "hook_event_name": "agentSpawn",
  "cwd": "/current/working/directory",
  "session_id": "abc123-def456-789"
}
```

**終了コードの挙動:**

- **0**: フックが成功し、STDOUTがエージェントのコンテキストに追加される
- **その他**: ユーザーに STDERR 警告を表示

**ユースケース:**

- セッション開始時に環境コンテキストを設定する
- プロジェクト固有の設定を読み込む
- ロギングまたは監査システムの初期化

## セッション終了（CLI V3のみ）

`SessionEnd`トリガーは、CLI V3セッションが切断されたときに発火します。

## ツール使用前

エージェントがツールを呼び出そうとする際にトリガーされます。ツールの使用を検証し、ブロックすることができます。

[**ツール名**] フィールドには、このフックを実行すべき特定のツールの名前を指定します。複数のエントリを指定できます。以下の組み込みカテゴリがサポートされています：

- **read** - すべての組み込みファイル読み取りツール
- **write** - すべての組み込みファイル書き込みツール
- **shell** - すべての組み込みシェルコマンド関連ツール
- **web** - すべての組み込みWebツール
- **spec** - すべての組み込みspecツール
- ***** - すべてのツール（組み込みおよびMCP）

また、プレフィックスフィルターを使用して、ソースごとにツールを絞り込むこともできます:

- **@mcp** - すべての MCP ツール
- **@powers** - すべての Powers ツール
- **@builtin** - すべての組み込みツール

`@` で始まるプレフィックスは正規表現でマッチするため、`@mcp.*sql.*` のようなパターンを使用して、特定の MCP ツールを名前で指定することができます。

利用可能なツールの名前については、Kiroに問い合わせることができます。

**使用例：**

- 特定のツールの実行をブロックする
- 実行前にツールの入力内容を検証する
- エージェントがツールを呼び出す前に、追加の指示を与える

## ツール使用後

エージェントがツールを呼び出した後にトリガーされ、ツールの結果にアクセスできます。

「**ツール名」**フィールドの詳細については、上記の「[ツール使用前」](https://kiro.dev/docs/hooks/types/#pre-tool-use)のセクションを参照してください。

**ユースケース：**

- 監査目的でツールの呼び出しを記録する
- 「書き込み」ツールの呼び出し後に、更新されたファイルのフォーマット調整や確認を行う
- ツールの応答に加えて、エージェントに追加の指示を提供する

## ファイル作成

エージェントがワークスペース内で特定のパターンに一致する新しいファイルを作成した際にトリガーされます。

**ユースケース：**

- 新しいコンポーネント用の定型コードを生成する
- 新しいファイルにライセンスヘッダーを追加する
- 実装ファイルの作成時にテストファイルを設定する

## ファイルの保存

エージェントが特定のパターンに一致するファイルを保存または変更したときにトリガーされます。

**ユースケース：**

- リンティングとフォーマットを実行する
- 関連ファイルの更新
- ドキュメントを生成する
- 変更されたファイルのテストを実行する

## ファイルの削除

エージェントが特定のパターンに一致するファイルを削除した際にトリガーされます。

**ユースケース：**

- 関連ファイルのクリーンアップ
- 他のファイル内のインポート参照を更新する
- プロジェクトの整合性を維持する

## タスク実行前

仕様タスクの実行開始前にトリガーされる。

**ユースケース：**

- タスク実行前にセットアップスクリプトを実行したり、環境の準備を行ったりする
- タスク開始前に前提条件が満たされていることを検証する
- 追跡のためにタスクの開始イベントをログに記録する

## タスク実行後

特定のタスクの実行が完了した後にトリガーされる。

**ユースケース：**

- タスク完了後にテストを実行し、正しさを検証する
- 変更されたファイルに対してリンティングやフォーマット処理を実行する
- 完了した作業のドキュメントを生成する
- タスクの完了を外部システムに通知する

## マニュアル（WebおよびCLI V3）

Kiro Web では、`Manual` がオンデマンドのフックを識別します。CLI V3 は `Manual` のフック定義を認識して一覧表示しますが、`/hooks` にはそれらを呼び出すアクションは用意されていません。

## レガシー手動フック（IDEのみ）

IDE 0.x で作成された手動フックは、引き続き「Agent Hooks」パネルに「**レガシー**」というラベル付きで表示されます。有効になっているレガシー手動フックは、フック名の横にある再生ボタン、またはフックビュー内の `Start Hook` を使用して実行可能です。

IDE 0.x の「`userTriggered`」フックには、v1 IDE における同等のトリガーが存在せず、IDE 内で新しい「Manual-trigger」フックを作成することはできません。新しい IDE オンデマンドワークフローを作成するには、[手動でインクルードするステアリングファイル](https://kiro.dev/docs/steering/#manual-inclusion)を作成してください。これは、`/<filename>` スラッシュコマンドとして実行されます。

## MCP ツールフック

MCP ツールの場合、ツール名には MCP サーバー名を含む完全な名前空間形式が含まれます:

json

```json
{
  "hook_event_name": "preToolUse",
  "cwd": "/current/working/directory",
  "session_id": "abc123-def456-789",
  "tool_name": "@postgres/query",
  "tool_input": {
    "sql": "SELECT * FROM orders LIMIT 10;"
  }
}
```

これは、MCP サーバーのツールを対象とする「ツール使用前」および「ツール使用後」のフックの両方に適用されます。
