エージェントフックは、特定の自動化シナリオに合わせて設計されたさまざまなトリガータイプに対応しています。これらのタイプを理解することで、ワークフローのニーズに適したアプローチを選択できるようになります。

## インターフェースごとの利用可能性

このページでは、`.kiro/hooks/*.json`に保存されるスタンドアロンのフック定義について説明します。インラインプロファイルのフックには、現行形式とレガシー形式の2種類があります。詳細については、[エージェント設定リファレンス](https://kiro.dev/docs/custom-agents/configuration-reference/#hooks-field)を参照してください。

ファイルおよびタスクのトリガーは、IDE および CLI V3 で利用可能です。Web では、後でローカルで使用するためにフックの設定を保存できますが、Web セッションではこれらのトリガーは実行されません。以下の表に、各環境で何がサポートされているかを示します。

## プロンプトの送信

ユーザーがプロンプトを送信したときにトリガーされます。

シェルコマンドアクションを使用する場合、ユーザープロンプトには`USER_PROMPT`環境変数を通じてアクセスできます。

**使用例:**

- プロンプトに関連する追加のコンテキストをエージェントに提供
- プロンプトの内容に基づいて特定のプロンプトをブロックする（IDEのみ。CLIのプロンプト送信フックではブロックできません）
- すべてのユーザープロンプトを一元的な場所に記録する

## エージェントの停止

エージェントがターンを完了し、ユーザーへの応答を終えたときにトリガーされます。

これは、エージェントの応答後に、コードのコンパイル、テスト、フォーマット、クリーンアップなどの後処理タスクを実行するのに役立ちます。

**ユースケース：**

- コードをコンパイルし、失敗があった場合はエージェントに報告する
- エージェントが生成したコードのフォーマットやレビューを行う
- エージェントによる変更内容をレビューし、追加の指示を出す

## セッション開始

IDEまたはCLI V3で新しいチャットセッションが開始されたときにトリガーされる。

**ユースケース：**

- エージェントのコンテキストにワークスペース固有の指示を挿入する
- 環境チェックを実行する（依存関係の確認、認証情報の検証）
- セッション開始時にプロジェクト固有の設定を読み込む

## エージェントの起動（CLI 2.x および V3 のエイリアス）

CLI 2.x では、エージェントが最初にアクティブ化された際に `agentSpawn` が使用されていました。CLI V3 では、`SessionStart` が標準的なトリガーとして使用されますが、互換性のため `AgentSpawn` および `agentSpawn` も受け付けます。このイベントではツールコンテキストは提供されません。

json

```json
{
  "hook_event_name": "agentSpawn",
  "cwd": "/current/working/directory",
  "session_id": "abc123-def456-789"
}
```

**終了コードの挙動:**

- **0**: フックが成功し、STDOUTがエージェントのコンテキストに追加される
- **その他**: ユーザーに STDERR 警告を表示

**ユースケース:**

- セッション開始時に環境コンテキストを設定する
- プロジェクト固有の設定を読み込む
- ロギングまたは監査システムの初期化

## セッション終了（CLI V3のみ）

`SessionEnd`トリガーは、CLI V3セッションが切断されたときに発火します。

## ツール使用前

エージェントがツールを呼び出そうとする際にトリガーされます。ツールの使用を検証およびブロックできます。

[**ツール名パターン**] フィールドには、正確なツール ID、組み込みカテゴリ、ソースセレクタ、または正規表現を指定します。複数のエントリを指定できます。以下の組み込みカテゴリがサポートされています：

- **read** - すべての組み込みファイル読み取りツール
- **write** - すべての組み込みファイル書き込みツール
- **shell** - すべての組み込みシェルコマンド関連ツール
- **web** - すべての組み込みWebツール
- **spec** - すべての組み込み仕様ツール

ソースセレクタも使用できます:

- **@mcp** - すべての MCP ツール
- **@powers** - すべての Powers ツール
- **@builtin** - すべての組み込みツール
- **`@<server>`** - 1つのMCPサーバー上のすべてのツール。例：`@postgres`
- **`@<server>/<tool>`** - 1つのMCPサーバー上の1つのツール（例：`@postgres/query`）

エディタは、各エントリをツール ID に対する正規表現としてチェックします。したがって、`read` のような単純な名前は、そのテキストを含む任意のツール ID と一致する可能性があります。すべてのツールに一致させるには、このフィールドを空白のままにしてください。

Hook JSON ファイルでもワイルドカードパターンを使用できます。任意の文字数を一致させるには `*` を、1 文字のみを一致させるには `?` を使用します。IDE エディタではこれらが無効な正規表現として拒否されるため、これらのパターンを使用するには Hook JSON ファイルを直接編集してください。

利用可能なツールの名前については、Kiroに問い合わせることができます。

**使用例：**

- 特定のツール呼び出しをブロックする
- 実行前にツールの入力内容を検証する
- エージェントがツールを呼び出す前に、追加の指示を与える

## ツール使用後

エージェントがツールを呼び出した後にトリガーされ、ツールの結果にアクセスできます。

「**ツール名」**フィールドの詳細については、上記の「[ツール使用前」](https://kiro.dev/docs/hooks/types/#pre-tool-use)のセクションを参照してください。

**ユースケース：**

- 監査目的でツールの呼び出しを記録する
- 「書き込み」ツールの呼び出し後に、更新されたファイルのフォーマット調整や確認を行う
- ツールの応答に加えて、エージェントに追加の指示を提供する

## ファイル作成

エージェントがワークスペース内で特定のパターンに一致する新しいファイルを作成した際にトリガーされます。

**ユースケース：**

- 新しいコンポーネント用の定型コードを生成する
- 新しいファイルにライセンスヘッダーを追加する
- 実装ファイルの作成時にテストファイルを設定する

## ファイルの保存

エージェントが特定のパターンに一致するファイルを保存または変更した際にトリガーされます。

**ユースケース：**

- リンティングとフォーマットを実行する
- 関連ファイルの更新
- ドキュメントを生成する
- 変更されたファイルのテストを実行する

## ファイルの削除

エージェントが特定のパターンに一致するファイルを削除した際にトリガーされます。

**ユースケース：**

- 関連ファイルのクリーンアップ
- 他のファイル内のインポート参照を更新する
- プロジェクトの整合性を維持する

## タスク実行前

仕様タスクの実行開始前にトリガーされる。

**ユースケース：**

- タスク実行前にセットアップスクリプトを実行したり、環境の準備を行ったりする
- タスク開始前に前提条件が満たされていることを検証する
- 追跡のためにタスクの開始イベントをログに記録する

## タスク実行後

特定のタスクの実行が完了した後にトリガーされる。

**ユースケース：**

- タスク完了後にテストを実行し、正しさを検証する
- 変更されたファイルに対してリンティングやフォーマット処理を実行する
- 完了した作業のドキュメントを生成する
- タスクの完了を外部システムに通知する

## マニュアル（CLI V3）

CLI V3 は `Manual` フックの定義を認識して一覧表示しますが、`/hooks` にはそれらを呼び出すアクションが用意されていません。

## レガシー手動フック（IDE のみ）

IDE 0.x で作成された手動フックは、**レガシー**というラベルが付いたまま「エージェントフック」パネルに引き続き表示されます。有効になっているレガシー手動フックは、フック名の横にある再生ボタン、またはフックビュー内の `Start Hook` を使用して引き続き実行可能です。

IDE 0.x の `userTriggered` フックには、v1 IDE トリガーに相当するものはなく、IDE 内で新しい手動トリガーフックを作成することはできません。新しい IDE オンデマンドワークフローを作成するには、[手動でインクルードするステアリングファイル](https://kiro.dev/docs/steering/#manual-inclusion)を作成してください。これは `/<filename>` スラッシュコマンドとして実行されます。

## MCP ツールフック

MCP ツールの場合、V3 フックイベントでは、`@server/tool` の表示名ではなく、サニタイズされた内部ツール ID `mcp_<server>_<tool>` が使用されます:

json

```json
{
  "hook_event_name": "PreToolUse",
  "cwd": "/current/working/directory",
  "session_id": "abc123-def456-789",
  "tool_name": "mcp_postgres_query",
  "tool_input": {
    "sql": "SELECT * FROM orders LIMIT 10;"
  }
}
```

これは、MCPサーバーツールを対象とする「ツール使用前」および「ツール使用後」のフックの両方に適用されます。フックの`matcher`では、`@<server>`または`@<server>/<tool>`セレクタ、あるいは内部IDに対する正規表現を使用してください。
