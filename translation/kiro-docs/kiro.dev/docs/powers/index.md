## コンセプト

### 問題：コンテキストの過剰負荷

**フレームワークによるコンテキストがなければ、エージェントは推測するしかありません。**エージェントはStripeのAPIを呼び出すことはできますが、冪等なキーを使用すべきことを知っているでしょうか？Neonにクエリを実行することはできますが、サーバーレス環境における接続プーリングを理解しているでしょうか？組み込みの専門知識がなければ、出力が正しくなるまで、ドキュメントを手作業で読み込み、アプローチを微調整し続けることになります。 「パワー」は、エージェント（ひいてはあなた自身）に専門知識への即時アクセスを提供するため、不慣れな領域でもより迅速に作業を進めることができます。

**コンテキストが多すぎると、エージェントの動作が遅くなります。**5台のMCPサーバーを接続すると、エージェントは1行のコードも書く前に100以上のツール定義を読み込むことになります。 5台のサーバーの場合、最初のプロンプトを入力する前に50,000以上のトークン（コンテキストウィンドウの40％）を消費してしまう可能性があります。ツールが増えれば結果も良くなるはずですが、構造化されていないコンテキストはエージェントを圧倒し、応答の遅延や出力の質の低下を招きます。

### パワーの仕組み

すべてのMCPツールを一度に読み込むのではなく、パワーは会話中のキーワードに基づいて動的に有効化されます。

タスクを開始すると、Kiroは以下の処理を行います：

1. タスクの説明を読み込み
2. インストール済みのパワーをタスクに対して評価します
3. 関連するパワーのみをコンテキストに読み込みます

### 「パワー」とは何でしょうか？

パワーは「[Agent Plugins](https://agent-plugins.org/)」仕様に準拠しています。これは、AIエージェントを拡張する再利用可能なコンポーネントをパッケージ化するための、オープンでベンダー中立なフォーマットです。パワーとは、必須のマニフェストとオプションのコンポーネントを含むディレクトリのことです：

1. **plugin.json** — パワーを識別し、起動用のキーワードを宣言するマニフェスト
2. **skills/** — タスク固有の指示、スクリプト、および参考資料を提供するエージェントスキル
3. **mcp.json** — ツール連携のための MCP サーバー設定（オプション）

```text
my-power/
├── plugin.json          # Required manifest
├── skills/              # Agent Skills
│   └── setup/
│       ├── SKILL.md
│       └── references/
└── mcp.json             # MCP server configuration
```

ワンクリックでStripeパワーをインストールできます。「payment」や「checkout」という単語が言及されると、パワーが起動し、StripeのMCPツールとスキルがコンテキストに読み込まれます。支払いの処理が完了してデータベース作業に移ると、Supabaseパワーが起動し、Stripeは非アクティブになります。

### パワーの特長

**ポータブルなプラグイン形式** — パワーは、Amazon、Cursor、Microsoft、OpenAI、Vercelがメンテナンスを行うオープンスタンダードである「[Agent Plugins](https://agent-plugins.org/)」仕様に準拠しています。一度構築すれば、互換性のあるエージェントクライアント間でパワーが動作します。

**動的なMCPツールの読み込み** — 従来のMCPサーバーは、すべてのツールを事前に読み込みます。パワーはオンデマンドでツールを読み込むため、ベースラインのコンテキスト使用量を削減しつつ、エージェントに数十種類のテクノロジーへのアクセスを提供します。

**オープンなエコシステム** — Datadog、Dynatrace、Figma、Neon、Netlify、Postman、Supabase、Stripe、Strands SDK、AWS Auroraなど、[レジストリから](https://kiro.dev/powers/)厳選されたパワーを閲覧できます。GitHubのURLからコミュニティが作成したパワーをインストールしたり、独自のパワーを作成して共有したりすることも可能です。

**ワンクリックインストール** — Kiro内または[kiro.dev/powersで](https://kiro.dev/powers/)直接「powers」を閲覧できます。「インストール」をクリックするだけで、自動的に登録されます。JSON設定ファイルも、コマンドラインでのセットアップも不要です。

## 「Powers」と「Skills」、「Steering」の違い

**[「Powers」](https://kiro.dev/docs/powers/)**は、MCPのツール、スキル、ナレッジを単一のインストール可能なパッケージにまとめたプラグインです。コンテキストに基づいて動的に起動します。ツールとガイダンスの両方が必要な統合に活用してください。「Powers」には、コンポーネントとしてスキルを含めることができます。

**[スキルは](https://kiro.dev/docs/skills/)**、エージェントが特定のタスクを遂行できるよう導く、スタンドアロンのポータブルな指示パッケージです。単独で存在することも、パワー内にバンドルされることもあります。共有やインポートしたい再利用可能なワークフローに使用します。

**[ステアリングは](https://kiro.dev/docs/steering/)**、エージェントの挙動を形作るKiro固有のコンテキストです。`always`、`auto`、`fileMatch`、および`manual`モードをサポートしています。プロジェクトの標準や規約に活用してください。

## IDEでクラウド同期されたパワーを使用する

クラウド同期された「Power」は、アカウントに紐付いた設定です。これらは、管理されたサンドボックス内でエージェントを実行する[クラウドセッション](https://kiro.dev/docs/cloud-sessions/)とは別物です。[「設定同期」](https://kiro.dev/docs/web/cloud-configuration/)を使用して、サポートされているローカルの「Power」を Kiro Web アカウントにアップロードしてください。 [Kiro](https://app.kiro.dev/settings/powers) Webの [**Agent Config] > [Powers & MCP]** で管理するPowerは、Kiro IDE 1.0.437以降の「インストール済みPower」リストに表示されます。各Powerにはクラウドインジケーターが付いています。**「Try power」**を選択して直接使用するか、詳細を開いてバンドルされたスキルやMCP設定を確認してください。

バンドルされたMCP設定は、そのPowerに紐付けられたままとなり、Powerとともに有効化されます。これは、独立した同期済みMCPサーバーではありません。`.kiro/settings/mcp.json`にあるプロジェクトMCPサーバーは、プロジェクト設定のままであり、リポジトリとともに移動します。個人用クラウド設定が、クラウドセッションやプロジェクト設定とどのように異なるかについては、[「クラウド上の設定」](https://kiro.dev/docs/cloud-sessions/#configuration-in-the-cloud)を参照してください。
