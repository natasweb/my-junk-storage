# Compaction

Compactionは、セッションが長くなるにつれて過去の会話履歴を自動的に要約することで、長時間のセッションでも生産性を維持します。目標、決定事項、技術的な進捗はそのまま保持され、冗長な中間部分のみが圧縮されます。

| 機能 | IDE | CLI | Web | モバイル |
| --- | --- | --- | --- | --- |
| 自動コンパクション | ✓ | ✓ | ✓ | ✓ |
| 手動起動（`/compact`） | — | ✓ | — | — |
| コンテキスト使用量メーター | ✓ | ✓ | ✓ | ✓ |

## 仕組み

会話がモデルのコンテキスト制限に近づくと、コンパクションが自動的にトリガーされます：

1. **要約の生成** - Kiroは、ユーザーの目標、決定事項、進捗状況、および次のステップを網羅した構造化された要約を作成します
2. **コンテキストの削減** - 古い会話履歴は要約に置き換えられますが、最新のメッセージはそのまま保持されます
3. **継続** - 中断することなく、中断した箇所からセッションを再開できます

あなたの目標、決定事項、ファイルの変更内容、および明示された制約条件は、コンパクション後も保持されます。圧縮されるのは中間出力、つまりツールの呼び出し詳細、探索的な議論、および解決済みのエラーメッセージです。

## 例

45分間にわたりリファクタリング作業を行ってきました。エージェントは12個のファイルを修正し、テストを実行し、3つのビルドエラーを修正しました。コンテキストの使用率は80%です。

コンパクションが実行されます。要約には、どのファイルが変更されたか、どのテストに合格したか、リファクタリングが必要な残りの2つのファイル、および「すべての変更は下位互換性を保たなければならない」という制約が記録されます。最後の2回のやり取り（あなたの最新の指示とエージェントの応答）は、そのままの形で保持されます。

エージェントは直ちに作業を再開します。45分間の中間的なツール出力を保持することなく、何が完了し、次に何を行うべきか、そしてあなたのルールが何であるかを把握しています。

## 保持される内容と要約される内容

| 常に保持されるもの | 要約される場合あり |
| --- | --- |
| タスクのステータス（完了／進行中／保留中） | 個々のツール呼び出しの詳細 |
| 変更されたファイルのパス | 中間的な推論の手順 |
| 主要な決定事項と制約 | 以前のメッセージ内のコードスニペット |
| 今後の手順 | 解決済み課題のエラー詳細 |
| ご提示いただいた意図と要件 | 検討のための議論 |

## コンパクションのトリガー

IDE ではコンパクションは自動的に実行されます。手動でトリガーすることはできません。

チャットパネルのコンテキスト使用量メーターは、モデルの制限値まであとどれくらい残っているかを示します。コンパクションが実行されると、メーターは解放された領域を反映してリセットされ、セッションは継続されます。

## 設定

CLI には、コンパクション中に保持されるコンテキストの量を制御する 2 つの設定があります:

| 設定 | デフォルト | 説明 |
| --- | --- | --- |
| `compaction.excludeMessages` | 2 | そのまま保持する直近のメッセージペアの最小数 |
| `compaction.excludeContextWindowPercent` | 2 | コンテキストウィンドウのうち、直近のメッセージとして保持する最小割合 |

両方の設定が評価され、より保守的な（大きい）値が優先されます。これにより、エージェントが会話の連続性を維持するために、常に十分な直近のコンテキストが利用可能になります。

## 制限事項

圧縮は一方向です。圧縮時点以前の会話履歴全体は、そのセッション内では復元できません。完全な履歴を保存する必要がある場合は、圧縮が行われる前にセッションをエクスポートしてください。

## 以前のバージョン

IDE 0.x では、この機能は「要約（Summarization）」と呼ばれていました。動作は類似していましたが（コンテキスト使用率が 80% で自動トリガー）、同じセッションを継続するのではなく、コンテキストを圧縮した新しいセッションが作成されていました。従来の動作については、[0.x リファレンスを](https://kiro.dev/docs/ide/0x-reference/#summarization-replaced-by-compaction-in-10)参照してください。
